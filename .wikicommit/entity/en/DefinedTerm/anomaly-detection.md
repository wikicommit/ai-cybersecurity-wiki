In data analysis, anomaly detection — also referred to as outlier detection, and sometimes as novelty detection — is generally understood to be the identification of rare items, events or observations that deviate significantly from the majority of the data and do not conform to a well-defined notion of normal behaviour. Such observations may arouse suspicion of having been generated by a different mechanism, or appear inconsistent with the rest of the data. It is an important subarea of unsupervised machine learning, and its applications include cybersecurity and [[DefinedTerm/intrusion-detection-system|intrusion detection]].

## What counts as an anomaly

There is no single operational definition of anomaly detection that applies to every domain, because what is "normal" depends on the data, how the observations are represented, the context in which they occur and the assumptions of the detection method. An anomaly is not necessarily a data error: depending on the application it may be a measurement or recording error, a change in the process that generated the data, an unusual but valid observation, or an event of interest such as fraud, equipment failure or a security intrusion. Nor is an anomaly defined solely by rarity or distance from other observations — different methods characterise normality through probability distributions, distances or local densities, cluster membership, boundaries around normal data, prediction errors, reconstruction errors or other model-specific criteria.

Many methods return a numerical **anomaly score** rather than an immediate label. The score expresses how far an observation departs from the fitted model of normality, and a decision threshold turns it into a binary decision — so whether an observation is labelled anomalous depends on the model of normality, the available context and the decision rule.

Anomalies were originally sought so that they could be rejected or omitted from data, to aid statistical analysis (for example computing a mean or standard deviation) and to improve predictions from models; in many applications, however, the anomalies themselves are the observations of most interest and need to be separated from noise or irrelevant outliers.

## Types of anomalies

A widely used classification distinguishes three types:

| Type | What it is | Example given by the source |
| --- | --- | --- |
| Point anomaly | An individual observation that is anomalous relative to the rest of the data | An unusually large transaction compared with the other transactions in a dataset |
| Contextual (conditional) anomaly | An observation anomalous only within a particular context — temporal, spatial, demographic or otherwise defined by the application | A temperature that is normal in summer but unusual in winter |
| Collective anomaly | A related collection of observations that is anomalous as a whole, even if its individual observations are not | An unusual subsequence in a time series, or an unexpected pattern of activity in a computer network |

Point-anomaly methods may suffice for independent observations, whereas time series, spatial data, sequences and graphs often need contextual or collective relationships to be modelled explicitly.

## Approaches by available labels

| Approach | What it assumes |
| --- | --- |
| Supervised | A data set labelled "normal" and "abnormal", used to train a classifier. Rarely used, because labelled data are generally unavailable and the classes are inherently unbalanced |
| Semi-supervised | Some portion of the data is labelled; most often a model of normal behaviour is built from normal training data and the likelihood that a test instance was generated by that model is tested |
| Unsupervised | The data are unlabelled; by far the most commonly used approach |

## Methods

Many techniques have been proposed. Their performance usually depends on the data set — some suit local outliers, others global ones — and compared across many data sets the methods have little systematic advantage over one another. Almost all require setting non-intuitive parameters that are critical for performance and usually unknown before application. The source groups popular techniques as follows:

| Category | Examples named by the source |
| --- | --- |
| Statistical, parameter-free | Histogram-based (frequency- or counting-based) scoring; kernel functions approximating the distribution of normal data |
| Statistical, parametric | Z-score, Tukey's range test, Grubbs's test |
| Density-based | k-nearest neighbour, local outlier factor, isolation forests; subspace-, correlation- and tensor-based outlier detection for high-dimensional data; one-class support vector machines |
| Neural networks and related models | Replicator neural networks, autoencoders and variational autoencoders, long short-term memory networks, Bayesian networks, hidden Markov models, minimum covariance determinant; deep learning including convolutional neural networks (for image and video data), simple recurrent units (for time series) and adapted foundation models |
| Cluster-based | Cluster-analysis-based outlier detection, deviations from association rules and frequent itemsets, fuzzy-logic-based detection |
| Ensembles | Feature bagging, score normalisation and different sources of diversity |
| Quantum | Quantum support vector machines and normalizing flows investigated on near-term quantum hardware |
| Other | Histogram-based Outlier Score (HBOS), which assumes feature independence for fast predictions |

Because many methods yield only a score, explainable anomaly detection seeks more detailed explanations: the Subspace Outlier Degree identifies the attributes in which a sample deviates, and Correlation Outlier Probabilities compute how a sample deviates from an expected location, which can be read as a counterfactual explanation.

Anomaly detection in dynamic networks — such as those representing financial systems, social-media interactions or transportation infrastructure — needs adaptive techniques because the relationships and states keep changing; the source lists community, compression, decomposition, distance and probabilistic-model anomalies as types found there.

## Use in security

Anomaly detection was proposed for intrusion detection systems by Dorothy Denning in 1986. Anomaly detection for intrusion detection is normally done with thresholds and statistics, but can also use soft computing and inductive learning; by 1999 the proposed features included profiles of users, workstations, networks, remote hosts, groups of users and programs, based on frequencies, means, variances, covariances and standard deviations. Its counterpart in intrusion detection is misuse detection.

The source traces intrusion detection from manual monitoring by system administrators, through retrospective analysis of audit and system logs in the late 1970s and early 1980s, to real-time intrusion detection systems in the 1990s that analysed audit data as it was generated, and later work on methods for larger and more complex networks.

Other security-related applications the source describes include:

- **Fraud detection** — anomaly detection is described as vital for fraud prevention in fintech.
- **Video surveillance** — deep-learning methods using convolutional neural networks and simple recurrent units have shown promise in identifying unusual activities in video, with scalable real-time frameworks needed to process many streams with low computational resources.
- **IT infrastructure** — detected anomalies help identify and pre-empt performance degradation or system failures.
- **IoT systems** — anomaly detection helps identify system failures and security breaches in networks of Internet of Things devices; one multi-stage framework the source cites combines spatial clustering, density-based clustering and locality-sensitive hashing.

Beyond security, the source lists fault detection, system health monitoring, event detection in sensor networks, ecosystem disturbances, defect detection in machine vision, medical diagnosis, law enforcement, and machinery and pipeline monitoring in the petroleum and oil-and-gas industries. Removing anomalies is also a preprocessing step: statistics such as the mean and standard deviation are more accurate afterwards, and in supervised learning it often yields a statistically significant increase in accuracy.

## Related terms

The terms anomaly, outlier and novelty are sometimes used interchangeably, but usage varies between statistics, machine learning, signal processing and application domains, and the distinctions are not applied consistently. An *outlier* commonly denotes an observation that appears inconsistent with the rest of a dataset, and outlier-detection methods often allow such observations to be present in the data used to fit the model. In *novelty detection*, the training data are generally assumed to represent normal behaviour and previously unseen observations are assessed against that model, so it is often formulated as one-class classification. The broader term anomaly detection is frequently used to cover all of these settings.

## Software and datasets

Open-source tools named by the source include the Java data-mining toolkit ELKI, the Python library PyOD (developed specifically for anomaly detection) and scikit-learn; Wolfram Mathematica also provides unsupervised anomaly detection. Public benchmark collections include the Anomaly detection benchmark data repository of Ludwig-Maximilians-Universität München, ODDS, the Unsupervised Anomaly Detection Benchmark at Harvard Dataverse and the KMASH Data Repository at Research Data Australia, which holds more than 12,000 datasets with ground truth.
