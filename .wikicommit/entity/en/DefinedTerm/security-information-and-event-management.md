Security information and event management (SIEM) is a field within computer security that combines security information management (SIM) and security event management (SEM) to enable real-time analysis of security alerts generated by applications and network hardware. SIEM systems are central to security operations centers (SOCs), where they are used to detect, investigate and respond to security incidents. They collect and aggregate data from many systems, which lets organizations meet compliance requirements while guarding against threats.

The National Institute of Standards and Technology (NIST) defines a SIEM tool as an "application that provides the ability to gather security data from information system components and present that data as actionable information via a single interface". SIEM tools can be implemented as software, hardware or managed services. They log security events and generate reports to meet regulatory frameworks such as the Health Insurance Portability and Accountability Act (HIPAA) and the Payment Card Industry Data Security Standard (PCI DSS).

## Origin and development

The term SIEM was introduced in 2005 by the Gartner analysts Mark Nicolett and Amrit Williams. It grew out of system logging, which was at first used mainly for troubleshooting and debugging; as operating systems and networks grew more complex, as cyberattacks became more sophisticated and as regulatory frameworks began to mandate logging security controls within risk management frameworks (RMFs), monitoring logs became increasingly common. From the late 1970s, working groups set criteria for managing auditing and monitoring programmes, and as information assurance matured in the late 1990s and 2000s the need to centralize system logs became apparent.

The term has since evolved to include features such as threat intelligence and behavioral analytics, which allow SIEM solutions to handle complex threats including zero-day vulnerabilities and polymorphic malware. Modern SIEM platforms aggregate and normalize data from operational technology (OT) in production and manufacturing as well as from information technology (IT) sources, and support response as well as detection — manual or automated, including AI-based response.

SIEM has also been incorporated into national cybersecurity initiatives. Executive Order 14028, "Improving the Nation's Cybersecurity", signed by US President Joe Biden on 17 May 2021 in response to an increase in ransomware attacks on critical infrastructure, mandates the use of SIEM technologies to improve incident detection and reporting in federal systems and established further logging requirements, including audit logging and endpoint protection.

## Place in security guidance

NIST SP 800-92, *Guide to Computer Security Log Management* (September 2006), guides what should be auditable within the NIST Risk Management Framework; it predates the widespread adoption of SIEM and does not use the term. Several regulations and standards reference NIST's logging guidance, including FISMA, the Gramm-Leach-Bliley Act, HIPAA, the Sarbanes-Oxley Act, PCI DSS and ISO 27001.

SIEM solutions are typically the central tools for three NIST SP 800-53 controls:

| Control | What it covers |
| --- | --- |
| AU-2 Event Monitoring | System auditing and continuous monitoring; federal systems categorized by their impact on confidentiality, integrity and availability have five logging requirements (AU-2 a–e). Logging every action is possible but generally not recommended, because of the volume of logs and the need for actionable data |
| SI-4 System Monitoring | Monitoring systems to detect unauthorized access and track anomalies, malware and potential attacks, including the hardware and software requirements for detecting suspicious activity |
| RA-10 Threat Hunting | Added in Revision 5; proactive network defense that identifies threats evading traditional controls, for which SIEM solutions aggregate security information for threat-hunting teams |

## Related terms

The acronyms SEM, SIM and SIEM have sometimes been used interchangeably, but generally refer to products with different primary focuses:

| Term | Primary focus |
| --- | --- |
| Log management | Simple collection and storage of log messages and audit trails |
| Security information management (SIM) | Long-term storage, analysis and reporting of log data |
| Security event manager (SEM) | Real-time monitoring, correlation of events, notifications and console views |
| SIEM | Combines SIM and SEM, providing real-time analysis of security alerts from network hardware and applications |

In practice many products mix these functions, and many vendors promote their own terminology. Log management alone does not give real-time insight into network security, and SEM on its own does not provide complete data for deep threat analysis; combining them gives a SIEM more information to monitor.

## Capabilities and components

| Capability | Description |
| --- | --- |
| Data aggregation | Consolidating monitored data from networks, security devices, servers, databases and applications so that crucial events are not missed |
| Correlation | Linking events with common attributes into meaningful bundles; typically a function of the SEM portion of a SIEM |
| Alerting | Automated analysis of correlated events |
| Dashboards | Turning event data into charts that help reveal patterns or activity that departs from them |
| Compliance | Automating the gathering of compliance data and producing reports for existing security, governance and auditing processes |
| Retention | Long-term storage of historical data, for correlation over time and for compliance; critical in forensic investigations because a breach is unlikely to be discovered when it happens |
| Forensic analysis | Searching logs across nodes and time periods by specific criteria |

Architectures vary by vendor, but the essential components are a data collector that forwards selected audit logs from a host; an ingest and indexing point for parsing, correlation and data normalization; and a search node for visualization, queries, reports and alerts, where analysis takes place.

## Use cases and rules

The computer security researcher Chris Kubecka presented a set of SIEM use cases at the hacking conference 28C3 (Chaos Communication Congress), including: using SIEM visibility and [[DefinedTerm/anomaly-detection|anomaly detection]] to help detect zero-days or polymorphic code, against which anti-virus detection rates are low; automatic parsing, normalization and categorization of logs from any device that can send one; visualizing security events and log failures to aid pattern detection; identifying protocol anomalies that may indicate a misconfiguration or security issue; detecting covert, malicious communications and encrypted channels; and detecting cyberwarfare, discovering both attackers and victims.

A SIEM can have hundreds or thousands of correlation rules, some simple and some complex. When a rule is triggered, the system can act to mitigate an attack — usually by notifying a user and possibly limiting or shutting down the system. Rule types described include brute-force detection (for example, a password entered 60 times in a minute), impossible travel (logins whose times and locations imply travel that could not happen, a rule that must allow for VPN services obscuring location), excessive file copying (which may indicate an attacker but also an employee selling or simply taking home files), network anomaly detection, DDoS attacks and file integrity change monitoring. Alerting rules are typically built on user authentication, attacks detected and infections detected — for example, alerting on three or more failed logins in one minute from a single host as an early warning of brute-force attacks, password guessing or misconfigured applications, with events drawn from sources such as Active Directory, syslog and RADIUS; or on a host that fails to clean detected malware within an hour.
