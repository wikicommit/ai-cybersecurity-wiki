OWASP Top 10 for LLM Applications は、[[Organization/owasp|OWASP]] が公開している、大規模言語モデル（LLM）を基盤とするアプリケーションにおける最も重大な10のセキュリティ脆弱性のリストである。LLM を使うアプリケーションやプラグインを設計・構築する開発者、データサイエンティスト、セキュリティ専門家に向けて書かれており、実践的で、実行可能で、簡潔なセキュリティガイダンスを提供することを目指している。バージョン1.1は2023年10月16日に公開された。OWASP のサイトでは、2023/24年版のリストと並んで、「Top 10 for 2025」も掲載されている。これは2025年版で、その項目には LLM01:2025 のようなコードが付いている。

このリスト自身の説明によれば、2022年後半に大衆向けの事前学習済みチャットボットが公開されたあと、開発チームが LLM を導入するペースに包括的なセキュリティプロトコルの確立が追いつかず、多くのアプリケーションが高リスクの問題にさらされたまま、開発者向けのガイダンスも散在していたことから、このリストが生まれた。

## 10の項目

各項目には LLM01 から LLM10 までのコードが付いている。リストはそれらを次のように要約している。

| コード | 項目 | 内容 |
| --- | --- | --- |
| LLM01 | [[DefinedTerm/prompt-injection\|プロンプトインジェクション]] | 巧妙に作られた入力が LLM を操作し、意図しない行動をとらせる。直接インジェクションはシステムプロンプトを上書きし、間接インジェクションは外部ソースからの入力を操作する |
| LLM02 | 安全でない出力処理 | LLM の出力が精査されないまま受け入れられ、バックエンドシステムに渡される。これは XSS、CSRF、SSRF、権限昇格、リモートコード実行につながりうる |
| LLM03 | [[DefinedTerm/data-poisoning\|訓練データポイズニング]] | 訓練データが改ざんされ、セキュリティ、有効性、倫理的な振る舞いを損なう脆弱性やバイアスが持ち込まれる |
| LLM04 | モデルのサービス拒否 | 攻撃者が LLM にリソースを大量に消費する処理を行わせ、サービスを劣化させたりコストを増大させたりする |
| LLM05 | サプライチェーンの脆弱性 | 脆弱なコンポーネントやサービス（サードパーティのデータセット、事前学習済みモデル、プラグイン）がアプリケーションのライフサイクルを損なう |
| LLM06 | 機密情報の漏洩 | LLM が応答の中で機密データを明かし、不正なデータアクセス、プライバシー侵害、セキュリティ侵害につながる |
| LLM07 | 安全でないプラグイン設計 | LLM のプラグインが安全でない入力と不十分なアクセス制御を備えているため、リモートコード実行に至るまで悪用されやすくなる |
| LLM08 | [[DefinedTerm/excessive-agency\|過剰なエージェンシー]] | LLM ベースのシステムが、過剰な機能、権限または自律性を与えられているために、意図しない結果をもたらす行動をとる |
| LLM09 | 過度の依存 | 人やシステムが監督なしに LLM に依存し、誤った、または不適切な出力による誤情報、誤解、法的問題、セキュリティ脆弱性にさらされる |
| LLM10 | モデルの窃取 | 独自の LLM モデルが許可なくアクセス、複製、または持ち出され、経済的損失や競争上の優位の喪失を招き、機密情報へのアクセスにつながるおそれもある |

## 2025年版

2025年版でも、プロンプトインジェクションは LLM01 のままである。機密情報の漏洩（バージョン1.1では LLM06）と過剰なエージェンシー（バージョン1.1では LLM08）は新しいコードで掲載されており、システムプロンプトの漏洩、ベクトルと埋め込みの脆弱性、誤情報、無制限の消費は、バージョン1.1のリストには現れない名称である。

| コード | 項目 | OWASP のサイトに掲載されている要約 |
| --- | --- | --- |
| LLM01:2025 | [[DefinedTerm/prompt-injection\|プロンプトインジェクション]] | ユーザーのプロンプトが、LLM の振る舞いや出力を意図しない形で変えるときに起こる |
| LLM02:2025 | [[DefinedTerm/sensitive-information-disclosure\|機密情報の漏洩]] | 個人を特定できる情報（PII）や財務の詳細を含む機密情報は、LLM とそのアプリケーションの文脈の両方に影響を及ぼしうる |
| LLM03:2025 | [[DefinedTerm/llm-supply-chain-vulnerabilities\|サプライチェーン]] | LLM のサプライチェーンは、訓練データ、モデル、デプロイの完全性に影響しうる脆弱性を抱えやすい |
| LLM04:2025 | [[DefinedTerm/data-poisoning\|データとモデルのポイズニング]] | 事前学習、ファインチューニング、または埋め込みのデータが操作され、脆弱性、バックドア、バイアスが持ち込まれる |
| LLM05:2025 | [[DefinedTerm/improper-output-handling\|不適切な出力処理]] | 大規模言語モデルが生成した出力の検証、サニタイズ、処理が不十分であること |
| LLM06:2025 | [[DefinedTerm/excessive-agency\|過剰なエージェンシー]] | 開発者が LLM ベースのシステムに与えるエージェンシー（関数を呼び出す能力など）の程度に関わる |
| LLM07:2025 | [[DefinedTerm/system-prompt-leakage\|システムプロンプトの漏洩]] | LLM で使われるシステムプロンプトや指示が漏洩するリスク |
| LLM08:2025 | [[DefinedTerm/vector-and-embedding-weaknesses\|ベクトルと埋め込みの脆弱性]] | LLM とともに検索拡張生成（RAG）を用いるシステムにおけるセキュリティリスク |
| LLM09:2025 | [[DefinedTerm/llm-misinformation\|誤情報]] | LLM が、もっともらしく見える虚偽または誤解を招く情報を生成すること。LLM に依存するアプリケーションにとっての中核的な脆弱性である |
| LLM10:2025 | [[DefinedTerm/unbounded-consumption\|無制限の消費]] | LLM アプリケーションがユーザーに過剰で制御されない推論の実行を許し、サービス拒否、経済的損失、モデルの窃取、サービスの劣化といったリスクにつながる |

LLM01:2025 の項目は、プロンプトインジェクションを MITRE ATLAS の3つの技術、AML.T0051.000（LLM Prompt Injection: Direct）、AML.T0051.001（LLM Prompt Injection: Indirect）、AML.T0054（LLM Jailbreak Injection: Direct）に関連づけている。LLM04:2025 の項目は、データとモデルのポイズニングを MITRE ATLAS の技術 AML.T0018（Backdoor ML Model）、および NIST AI リスクマネジメントフレームワークに関連づけている。LLM07:2025 の項目は、システムプロンプトの漏洩を AML.T0051.000（LLM Prompt Injection: Direct (Meta Prompt Extraction)）に関連づけている。LLM09:2025 の項目は、誤情報を AML.T0048.002（Societal Harm）に関連づけている。LLM10:2025 の項目は、無制限の消費を、ATLAS の戦術 AML.TA0000（ML Model Access）と技術 AML.T0024、AML.T0029、AML.T0034、AML.T0025、CWE-400（Uncontrolled Resource Consumption）、そして OWASP Machine Learning Security Top Ten の ML05:2023 Model Theft と API4:2023 Unrestricted Resource Consumption に関連づけている。

## 項目の書き方

バージョン1.1のすべての項目は同じ構成をとっている。説明、脆弱性のよくある例、防止策と緩和策、攻撃シナリオの例、参考リンクである。バージョン1.1の項目が推奨している対策の一部を以下に示す。

| 項目 | リストが推奨する対策（抜粋） |
| --- | --- |
| プロンプトインジェクション | バックエンドシステムへの LLM のアクセスに対する権限制御、特権的な操作への人間の関与（ヒューマン・イン・ザ・ループ）、外部コンテンツとユーザープロンプトの分離、そして信頼境界をまたいで LLM を信頼できないユーザーとして扱うこと。この項目は、LLM が指示と外部データを分離しないため、LLM 内部での確実な防止策は存在しないと述べている |
| 安全でない出力処理 | ゼロトラストのアプローチでモデルを他のユーザーと同様に扱うこと、応答がバックエンドの機能に届く前に検証すること、そして OWASP Application Security Verification Standard（ASVS）に従ってユーザーに返す出力をエンコードすること |
| 訓練データポイズニング | 訓練データのサプライチェーンを検証すること、モデルが意図しないデータソースをスクレイピングしないようサンドボックス化すること、訓練データへのフィルタリングと異常検知、そして訓練済みモデルにポイズニングの兆候がないかテストすること |
| モデルのサービス拒否 | 入力の検証、リクエストごとのリソース使用量の上限設定、API のレート制限、キューに入れられるアクションの制限、リソース使用量の監視、そしてコンテキストウィンドウに基づく入力の制限 |
| サプライチェーンの脆弱性 | データソースと供給業者の審査、信頼できるプラグインの使用、ソフトウェア部品表（SBOM）の維持、モデルとコードへの署名、そしてパッチ適用のポリシー。この項目は、執筆時点では SBOM がモデル、その成果物、データセットを対象としていなかったと指摘している |
| 機密情報の漏洩 | ユーザーデータが訓練データに入らないようにするためのデータのサニタイズ、入力の検証、そして、より低い権限のユーザーに表示されるおそれがある場合に、最も高い権限のユーザーがアクセスできる情報でモデルを訓練しないこと |
| 安全でないプラグイン設計 | 厳密にパラメーター化され型チェックされた入力、ASVS の入力検証とアクセス制御のガイダンス、OAuth2 などの認証、そして機微なプラグインが行うアクションに対するユーザーの手動での確認 |
| 過剰なエージェンシー | LLM エージェントが呼び出せるプラグインやツール、それらが実装する機能、それらが持つ権限を制限すること、アクションに対する人間の承認、そして LLM ではなく下流のシステムで認可を行うこと |
| 過度の依存 | LLM の出力の監視と相互確認、既知の事実に対する自動検証、LLM のリスクと限界を伝えること、そして開発で LLM を使う場合のセキュアコーディングの実践 |
| モデルの窃取 | モデルのリポジトリと訓練環境に対する強固なアクセス制御と認証、ネットワークリソースへの LLM のアクセスの制限、アクセスログの監視、レート制限、そして電子透かし |

## 項目どうしの関係

リストは、自身の項目の間にいくつかの線引きをしている。

- **安全でない出力処理と過度の依存**：安全でない出力処理は、下流に渡される前の LLM の出力に関わる。過度の依存は、その出力の正確さや適切さへの、より広い依存に関わる。2025年版の LLM05:2025 不適切な出力処理の項目も、不適切な出力処理と過度の依存の間に同じ線を引いている。
- **過度の依存と誤情報**：2025年版の LLM09:2025 誤情報の項目は、バージョン1.1の LLM09 の名称である過度の依存を関連する問題として扱っている。LLM が生成したコンテンツへのユーザーの過度の信頼が、誤情報の影響を悪化させるというものである。
- **過剰なエージェンシーと安全でない出力処理**：過剰なエージェンシーは、LLM ベースのシステムが、誤作動の原因（ハルシネーション、プロンプトインジェクション、悪意あるプラグイン、性能の低いモデル）が何であれ、とりうる有害な行動に関するものであり、出力の精査が不十分であることに関わる安全でない出力処理とは異なる。
- **安全でないプラグイン設計とサプライチェーンの脆弱性**：安全でないプラグイン設計は LLM のプラグインを書くことを扱い、サードパーティのプラグインを使うことのリスクはサプライチェーンの脆弱性に含まれる。
- **プロンプトインジェクションと訓練データポイズニング**：LLM アプリケーションへのクライアントの入力が、十分なサニタイズやフィルタリングなしにモデルの訓練に使われる場合、プロンプトインジェクションは訓練データポイズニングの攻撃ベクトルになりうる。

## リストの作られ方

このリストは、500人近くの専門家からなる国際的なチームによって作成され、AI 企業、セキュリティ企業、ISV、クラウドのハイパースケーラー、ハードウェアプロバイダー、学術界から125人を超える活発な貢献者が参加した。1か月にわたるブレインストーミングの間に、チームのメンバーは43の異なる脅威を書き出し、数回の投票を経て、それらを最も重大な10個に絞り込んだ。その後、専任のサブチームが、例、防止のヒント、攻撃シナリオ、参考文献とともに各項目を練り上げ、パブリックレビューにかけた。

## 利用法と他の OWASP リストとの関係

このリストには、仮想的な LLM アプリケーションの高レベルのアーキテクチャ図が含まれており、アプリケーションのフローの上に各項目のリスク領域が重ねて示されている。これは、リスクがアプリケーションのエコシステム全体にどのように影響するかを視覚的に示すガイドである。

このリストは他の OWASP Top 10 のリストと脆弱性の種類を共有しているが、その表明された目的はそれらを繰り返すことではない。LLM を使うアプリケーションにおけるそれらの固有の意味合い、従来の脆弱性が異なるリスクをもたらしたり新たな方法で悪用されたりしうる仕組み、そして開発者が従来の対処法をどのように適応させなければならないかを検討することである。いくつかの項目は、問題の従来からある部分について他の OWASP の資料を参照している。入力の検証、出力のエンコード、アクセス制御については ASVS、サプライチェーンのコンポーネントについては OWASP Top Ten のカテゴリー A06:2021（Vulnerable and Outdated Components）、そして通常 REST API であるプラグインについては OWASP Top 10 API Security Risks – 2023 である。
