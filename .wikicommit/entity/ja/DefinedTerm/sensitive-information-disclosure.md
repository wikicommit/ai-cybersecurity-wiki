機密情報の漏洩（sensitive information disclosure）とは、大規模言語モデル（LLM）、とりわけアプリケーションに組み込まれた LLM が、その出力を通じて機密データ、独自のアルゴリズム、秘密の詳細情報を露出させ、不正なデータアクセス、プライバシー侵害、知的財産の侵害につながるリスクである。[[DefinedTermSet/owasp-top-10-for-llm-applications|OWASP Top 10 for LLM Applications]] の2025年版の項目 LLM02:2025 にあたる。

## 何が機密にあたるか

OWASP の項目によれば、機密情報は LLM とそのアプリケーションのコンテキストの両方に影響しうる。これには個人を特定できる情報（PII）、財務情報、健康記録、企業の機密データ、セキュリティ認証情報、法的文書が含まれる。独自開発のモデルにも、機密とみなされる独自の学習手法やソースコードがある場合があり、クローズドモデルや基盤モデルでは特にそうである。

この項目は利用者にも向けられている。ユーザーは、意図せず提供した機密データが後にモデルの出力で開示されるおそれがあるというリスクを理解しておく必要がある。

## よくある形態

| 形態 | 何が起こるか |
| --- | --- |
| PII の漏洩 | LLM とのやり取りの中で、個人を特定できる情報が開示される |
| 独自アルゴリズムの露出 | 設定の不十分なモデル出力が、独自のアルゴリズムやデータを明らかにしてしまう。学習データが明らかになると、モデルが反転攻撃（inversion attack）にさらされうる。反転攻撃では、攻撃者が機密情報を抽出したり入力を再構成したりする |
| 企業の機密データの開示 | 生成された応答に、企業の機密情報がうっかり含まれてしまう |

独自アルゴリズムの露出の例として、この項目は「Proof Pudding」攻撃（CVE-2019-20634）を挙げている。この攻撃では、開示された学習データが[[DefinedTerm/model-extraction|モデル抽出]]と反転を容易にし、攻撃者は機械学習アルゴリズムのセキュリティ管理策を回避して、メールフィルタをすり抜けることができた。

この項目が示す攻撃シナリオの例は次のとおりである。データのサニタイズが不十分なために、ユーザーが他のユーザーの個人データを含む応答を受け取ってしまうもの。攻撃者が入力フィルタを回避し、標的を絞った[[DefinedTerm/prompt-injection|プロンプトインジェクション]]によって機密情報を抽出するもの。そして、学習に不注意にデータを含めたことが開示につながるものである。

## 予防と緩和

この項目の基本的な助言は、LLM アプリケーションはユーザーデータが学習モデルに入らないようデータを適切にサニタイズすべきであり、アプリケーションの所有者は、ユーザーが自分のデータを学習に使われないようオプトアウトできる、明確な利用規約ポリシーを示すべきだというものである。LLM が返すべきデータの種類についてシステムプロンプトで制限を設けることで漏洩を緩和できるが、そうした制限は常に守られるとは限らず、プロンプトインジェクションやその他の手法によって回避されうる。

この項目は予防策を次のようにまとめている。

| 分類 | 対策 |
| --- | --- |
| サニタイズ | 学習に使う前に機密コンテンツをサニタイズ、スクラビング、マスキングする仕組みを組み込む。有害な入力や機密性の高い入力を検出して除外するために、厳格な入力検証を行う |
| アクセス制御 | 最小権限の原則に基づく厳格なアクセス制御を徹底する。モデルによる外部データソースへのアクセスを制限し、実行時のデータオーケストレーションを安全に管理する |
| 連合学習とプライバシー技術 | 複数のサーバーやデバイスに分散して保存されたデータで学習し、データの集中的な収集を最小限にする。[[DefinedTerm/differential-privacy\|差分プライバシー]]を取り入れ、データや出力にノイズを加えて、個々のデータ点をリバースエンジニアリングしにくくする |
| ユーザー教育と透明性 | ユーザーが機密情報を入力しないよう導き、安全な利用方法について教育する。データの保持、利用、削除について明確なポリシーを維持し、ユーザーが学習へのデータ利用をオプトアウトできるようにする |
| 安全なシステム設定 | ユーザーがシステムの初期設定を上書きしたりアクセスしたりする能力を制限することで、システムのプリアンブルを秘匿する。エラーメッセージや設定の詳細から情報が漏れないよう、「OWASP API8:2023 Security Misconfiguration」などのガイドラインに従う |
| 高度な技術 | プライバシーを保護する機械学習のために準同型暗号を用い、モデルがデータを処理する間もデータの機密性を保つ。トークン化とパターンマッチングによる墨消しを用いて、処理の前に機密コンテンツをサニタイズする |

## 関連する技術

この項目は、この脆弱性を MITRE ATLAS の3つの技術、AML.T0024.000（Infer Training Data Membership）、AML.T0024.001（Invert ML Model）、AML.T0024.002（Extract ML Model）と関連づけている。
