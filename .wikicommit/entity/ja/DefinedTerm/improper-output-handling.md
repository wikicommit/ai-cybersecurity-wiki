不適切な出力処理（improper output handling）とは、大規模言語モデル（LLM）が生成した出力を、下流の他のコンポーネントやシステムに渡す前に行う検証、サニタイズ、処理が不十分であることをいう。[[DefinedTermSet/owasp-top-10-for-llm-applications|OWASP Top 10 for LLM Applications]] の2025年版の項目 LLM05:2025「Improper Output Handling」にあたる。LLM が生成するコンテンツはプロンプト入力によって制御されうるため、この項目は、この振る舞いをユーザーに追加の機能への間接的なアクセスを与えることにたとえている。悪用に成功すると、ウェブブラウザではクロスサイトスクリプティング（XSS）やクロスサイトリクエストフォージェリ（CSRF）、バックエンドシステムではサーバーサイドリクエストフォージェリ（SSRF）、権限昇格、リモートコード実行が生じうる。

## 過度の依存との違い

この項目は、不適切な出力処理を過度の依存（overreliance）と区別している。不適切な出力処理は、LLM が生成した出力を下流に渡す前の段階を扱うのに対し、過度の依存は、LLM の出力の正確さや適切さに過度に依存することについてのより広い懸念に焦点を当てる。

## 影響を大きくする要因

この項目は、この脆弱性の影響を大きくしうる条件を挙げている。

- アプリケーションが LLM にエンドユーザー向けに意図された以上の権限を与えており、権限昇格やリモートコード実行を可能にしている
- アプリケーションが間接的な[[DefinedTerm/prompt-injection|プロンプトインジェクション]]攻撃に対して脆弱であり、攻撃者が標的ユーザーの環境への特権的なアクセスを得られる可能性がある
- サードパーティの拡張機能が入力を十分に検証していない
- 出力がそのコンテキスト（たとえば HTML、JavaScript、SQL）に応じて適切にエンコードされていない
- LLM の出力の監視とログ記録が不十分である
- LLM の利用に対するレート制限や異常検知がない

## 事例

| 出力の行き先 | 起こりうる結果 |
| --- | --- |
| システムシェル、または `exec` や `eval` のような類似の関数に直接 | リモートコード実行 |
| ブラウザが解釈する JavaScript や Markdown としてユーザーに返される | XSS |
| 適切なパラメータ化なしに実行される SQL クエリ | SQL インジェクション |
| 適切なサニタイズなしに構築されるファイルパス | パストラバーサル |
| 適切なエスケープのないメールテンプレート | フィッシング攻撃 |

この項目の攻撃シナリオ例には次のようなものがある。チャットボットの汎用 LLM が応答を検証せずに管理機能をもつ拡張機能に渡し、その拡張機能がメンテナンスのために停止してしまうもの。ウェブサイト要約ツールの LLM がページ上のプロンプトインジェクションに従い、サイトやユーザーの会話から機密データをエンコードして、出力の検証やフィルタリングなしに攻撃者が管理するサーバーに送信するもの。SQL クエリを作成するチャット機能で、精査されないままのすべてのテーブルを削除するクエリによって、実際にテーブルが削除されてしまうもの。そして、マーケティング用のメールテンプレートを生成する LLM を攻撃者が操作し、悪意ある JavaScript を含ませるものである。さらに別のシナリオは、自然言語の入力から生成されるコードに関するもので、機密情報の露出、安全でないデータ処理の作り込み、SQL インジェクションのような脆弱性の混入といったリスクがある。項目は、モデルが存在しないソフトウェアパッケージをハルシネーションで生み出し、開発者がマルウェアに感染したリソースをダウンロードしてしまう可能性があることを付け加え、徹底したコードレビューと提案されたパッケージの検証が極めて重要であるとしている。

## 予防

この項目の予防・緩和戦略は次のとおりである。

- モデルを他のあらゆるユーザーと同様に扱うゼロトラストのアプローチをとり、モデルからバックエンドの関数に渡される応答に適切な入力検証を適用すること
- 効果的な入力検証とサニタイズのために、OWASP Application Security Verification Standard（ASVS）のガイドラインに従うこと
- JavaScript や Markdown による望ましくないコード実行を緩和するために、ユーザーに返すモデルの出力をエンコードすること（ASVS が詳細な指針を示している）
- ウェブコンテンツには HTML エンコーディング、データベースクエリには SQL エスケープなど、出力が使われる場所に基づくコンテキストに応じた出力エンコーディング
- LLM の出力を伴うすべてのデータベース操作に、パラメータ化クエリまたはプリペアドステートメントを用いること
- LLM が生成したコンテンツによる XSS のリスクを緩和するための、厳格なコンテンツセキュリティポリシー（CSP）
- 悪用の試みを示しうる LLM の出力の異常なパターンを検出するための、堅牢なログ記録と監視
