サプライチェーン攻撃とは、組織のサプライチェーンにおけるセキュリティの弱い要素を標的にすることで、その組織に損害を与えようとするサイバー攻撃である。金融業界や石油業界から政府まで、あらゆる業界で、またソフトウェアでもハードウェアでも起こりうる。攻撃者は通常、マルウェアやハードウェアベースのスパイ用部品を組み込むことで、製品の製造や流通に手を加える。Symantec の 2019年版 Internet Security Threat Report は、2018年にサプライチェーン攻撃が 78% 増加したと述べている。

## 意味

この用語は広く、普遍的に合意された定義はない。サイバーセキュリティでは、主に二つの意味で用いられる。

| 意味 | 攻撃される対象 |
| --- | --- |
| ハードウェアの改ざん | コンピュータ、ATM、電力システム、工場のデータネットワークなどの電子機器を物理的に改ざんし、サプライチェーンネットワークのより下流にいる関係者に害を与える、検出不能なマルウェアを組み込む |
| ソフトウェアサプライチェーン | 他のソフトウェアが使用する、一見低レベルで重要でないソフトウェアコンポーネントを利用して、それに依存するより大きなソフトウェアに悪意あるコードを注入する |

より一般的な意味では、サプライチェーン攻撃は電子機器をまったく伴わなくてもよい。2010年に製薬会社の供給倉庫から 8,000万米ドル相当の処方薬が盗まれた事件も、サプライチェーン攻撃と表現できる。

## 攻撃の進み方

情報システムに対するサプライチェーン攻撃は一般に、標的組織に到達するために、供給ネットワークの中でサイバーセキュリティが最も弱いメンバーを特定する持続的標的型攻撃（APT）から始まる。攻撃者は通常、米国政府のような大きな主体を直接攻撃するのではなく、その主体が使用している、しばしば防御の手薄なサードパーティのソフトウェアを標的にする。サプライチェーンネットワークは、相互に接続された多数の構成要素からなるため、特に脆弱であると考えられている。Verizon Enterprise の調査では、その調査対象のセキュリティインシデントの 92% が小規模企業の間で発生していた。APT は生産中の製品を物理的に改ざんすることもある。2008年10月には、欧州の法執行当局が、中国で製造されたクレジットカード読み取り機に挿入された追跡不能な装置を用いたクレジットカード詐欺組織を摘発した。推定損失は 1億米ドルにのぼった。

出典は、挙げている事例の中でいくつかの侵入経路を示している。

- 侵害されたソフトウェアアップデート（SolarWinds Orion、M.E.Doc、Notepad++、eScan）
- 海賊版サイトに投稿された、人気のあるコンパイラの感染した海賊版。Apple の Xcode や Microsoft Visual Studio の改変版など
- 広く使われているオープンソースライブラリに仕込まれたバックドア（XZ Utils）
- 公開パッケージレジストリにおけるタイポスクワッティングされたパッケージ（npm）
- サードパーティの供給業者から盗まれた認証情報（Target）
- ウェブサイトの決済ページに注入された悪意あるコード（British Airways）
- 技術者など内部アクセス権を持つ人物によって ATM に仕掛けられたマルウェア

## リスク

このリスクは情報技術に限られない。サプライチェーン攻撃は、石油業界、大手小売業者、製薬部門、そして複雑な供給ネットワークを持つ事実上あらゆる業界に影響する。Information Security Forum は、このリスクの原因を、サプライチェーンが機能するために必要な供給業者との情報共有にあるとし、サプライチェーン内で侵害された情報は、組織内部で侵害された情報と同じくらい大きな損害をもたらしうると指摘している。National University of Computer and Emerging Sciences の研究者は、このリスクを、露出点の数を増やすグローバル化、分散化、アウトソーシングと結びつけ、サプライチェーンへの攻撃は、その波及効果のために、つながり合う多数の主体に一度に損害を与える最も破壊的な方法であると述べている。管理の不十分なサプライチェーン管理システムは、顧客の機密情報の喪失、製造の中断、評判の失墜につながりうる。

## 事例

| 時期 | 事件 | 出典の報告内容 |
| --- | --- | --- |
| 2013年11月〜12月 | Target | 米国の 1,800 以上の店舗の POS システムに仕込まれたマルウェアにより、約 4,000万人の顧客のカードが露出した。調査担当者は、攻撃者が空調（HVAC）業者から盗んだ認証情報を使って侵入したと疑っているが、これは公式には確認されていない |
| — | Stuxnet | 産業用制御システムを標的とするコンピュータワームで、米国とイスラエルの共同作戦であると広く信じられている（両国政府とも確認していない）。感染した USB ドライブを介してイランのナタンズ施設に持ち込まれた |
| 2014年3月（Tyupkin） | ATM マルウェア（Suceful、Plotus、Tyupkin、GreenDispenser） | 内部アクセス権を持つ人物によって ATM に仕掛けられたマルウェアで、攻撃者はカードデータを取得したり現金を引き出したりできた |
| 2017年6月 | NotPetya / M.E.Doc | セキュリティ研究者は、ウクライナの財務ソフトウェア M.E.Doc の侵害されたアップデートを NotPetya の初期侵入経路の可能性が高いものとして特定した。一部のアナリストはこれをサプライチェーン攻撃と呼んだが、正確な手法は確定的には特定されておらず、開発元は当初この主張を否定した |
| 2018年8月〜9月 | British Airways | ウェブサイトの決済部分に注入されたコードが、カードデータを類似ドメインに送信した。Magecart が背後にいると考えられており、約 38万人の顧客が影響を受けた |
| 2020年 | SolarWinds | 出典がロシアのハッカーと表現する攻撃者が、ネットワーク管理ソフトウェア Orion のアップデートに悪意あるコードを注入した。約 1万8,000 の主体が影響を受け、侵害が確認された米国政府機関は 10 未満だった。記録に残る最初の Golden SAML 攻撃とされている |
| 2021年 | Microsoft Exchange Server | 自社運用の Exchange Server の欠陥が悪用され、米国の 2万以上の組織にバックドアが仕込まれた |
| 2021年7月 | Kaseya VSA | REvil グループが Kaseya のリモート監視・管理ソフトウェアの脆弱性を悪用し、約 60 のマネージドサービスプロバイダーと 1,000 社以上の企業が影響を受けた |
| 2023年3月 | 3CX | 3CX Phone System アプリの悪意あるインストーラーがインフォスティーラーを配布した。Gopuram バックドアが使われていたことから、北朝鮮のグループ Lazarus の関与が示唆された |
| 2024年3月 | XZ Utils のバックドア | xz/liblzma のバージョン 5.6.0 と 5.6.1 に含まれる悪意あるコードは、一般的なサードパーティ製の SSH パッチと組み合わさることで、攻撃者が sshd の認証を破ることを可能にしえた。影響を受けたのは主に開発ブランチの Linux ディストリビューションだった |
| 2024年10月 | npm のタイポスクワッティング | 287 を超えるタイポスクワッティングされたパッケージが、Ethereum のスマートコントラクトを使って、インストールされたマルウェアにコマンド＆コントロールサーバーのアドレスを伝えていた。これにより、サーバーが停止させられてもアドレスを変更できた |
| 2025年6月〜12月 | Notepad++ | 攻撃者がホスティングプロバイダーのレベルでアップデート基盤を侵害し、アップデートの通信を自らのサーバーへリダイレクトした。研究者は攻撃主体を中国の国家支援グループと評価し、Rapid7 は Lotus Blossom によるものとした |
| 2026年1月20日 | eScan | 攻撃者が eScan アンチウイルスの地域アップデートサーバーに侵入し、約 1時間にわたって正規のコンポーネントをマルウェアに置き換えた。攻撃主体の特定はなされていない |

## 防止

防止のアプローチは、サプライチェーンのレジリエンスを中心としている。あるサプライチェーンリスク管理の専門家の言葉を借りれば、それは「予期しない混乱に対処するサプライチェーンの能力」であり、サプライチェーンのどこが最も侵入を受けやすいかを全社的に認識することも含まれる。

| 主体 | 示されている対策 |
| --- | --- |
| 米国政府 | 大統領令 14028『Improving the nation's cybersecurity』（2021年5月12日）は、NIST をはじめとする機関に米国のサイバーセキュリティの強化を課した。2021年7月11日、NIST は CISA および OMB とともに、重要なソフトウェアの利用者向けのガイダンスと、ソフトウェアサプライチェーンのセキュリティと完全性について供給業者が行うべき最低限のテストに関するガイダンスを提出し、その後も大統領令のスケジュールに沿って、サプライチェーンのソフトウェアに関するさらなるガイドラインを示した。包括的国家サイバーセキュリティ・イニシアティブ（Comprehensive National Cybersecurity Initiative）とサイバースペース政策レビュー（Cyberspace Policy Review）は、連邦政府の資金をグローバルなサプライチェーンリスク管理に振り向けている |
| 英国政府 | 2015年3月に発表された、中小企業を保護するための取り組み。サプライチェーンのレジリエンスを高める施策や、Cyber Essentials Scheme を含む |
| 金融機関 | Depository Trust and Clearing グループは、ソフトウェアがどこでコーディングされ、ハードウェアがどこで製造されたかを含め、サプライチェーン全体の脆弱性管理を統制している。2014年の PwC の報告書は、経営陣がサイバーリスクに責任を持つことを推奨している |
| セキュリティ企業 | FireEye は、供給業者の数を少なく抑えること、厳格なベンダー管理（承認されたプロトコル、現地監査）、設計段階からセキュリティを組み込むことを推奨している。Kaspersky Lab の研究者は、セキュリティポリシーと教育、ネットワークセキュリティ、システム管理、そしてパッチ適用、アプリケーション制御、ホワイトリスト化、デフォルト拒否モードといった専門的な管理策を推奨している |
| 供給業者としてのセキュリティベンダー | オーストリア商工会議所と AV-Comparatives による 2025年の調査では、調査対象となった 14 社のセキュリティベンダーのうち、ソフトウェア部品表、透明性のあるデータ保管、詳細なインシデント報告、顧客がソースコードやアップデートを検査できる仕組みといった保証を提供していたのは 3 社のみだった |
