侵入検知システム（IDS）とは、ネットワークやシステムを監視し、悪意ある活動やポリシー違反を検知する装置またはソフトウェアアプリケーションである。IDS が見つけた侵入活動や違反は通常、管理者に報告されるか、セキュリティ情報イベント管理（SIEM）システムに集約される。SIEM システムは複数の情報源からの出力を組み合わせ、アラームのフィルタリング手法を用いて悪意ある活動と誤報を区別する。IDS の対象範囲は、単一のコンピュータから大規模なネットワークまでさまざまである。

## IDS の種類

IDS は、検知を行う場所と、用いる検知手法によって分類される。

| 検知を行う場所による分類 | 監視対象 |
| --- | --- |
| ネットワーク型侵入検知システム（NIDS） | ネットワーク上のすべての機器との間の通信を、戦略的な1つまたは複数の地点から監視する。サブネット全体を通過するトラフィックを分析し、既知の攻撃のライブラリと照合する。NIDS にはオンライン型（インライン。パケットをリアルタイムで分析する）とオフライン型（タップモード。保存されたデータを処理する）がある |
| ホスト型侵入検知システム（HIDS） | 単一のホストまたは機器。その送受信パケットや、システムファイルのスナップショットを以前のスナップショットと比較し、重要なファイルが変更または削除されたときに警告する |

| 検知手法による分類 | 仕組み | 長所と短所 |
| --- | --- | --- |
| シグネチャ型 | ネットワークトラフィック内のバイト列や、マルウェアが用いる既知の悪意ある命令列など、特定のパターンを探す。この用語はアンチウイルスソフトウェアに由来する | 既知の攻撃は容易に検知できるが、パターンが存在しない新しい攻撃には弱い。ベンダーが公開するシグネチャを常に最新に保つ必要がある |
| アノマリ型 | 機械学習を用いて信頼できる活動のモデルを構築し、新しい振る舞いをそれと比較する | 未知の攻撃を検知できるが、これまで知られていなかった正当な活動が悪意あるものと分類されると誤検知を生じうる |
| レピュテーション型 | レピュテーションスコアから潜在的な脅威を認識する | — |

## 侵入検知における機械学習

アノマリ型のシステムは、主に未知の攻撃を検知するために導入された。その一因はマルウェアの急速な発展である。モデルを特定のアプリケーションやハードウェア構成に合わせて訓練できるため、機械学習のアプローチは従来のシグネチャ型の検知よりも汎化性能が高い。効率的な特徴選択アルゴリズムは検知に用いられる分類の信頼性を高め、最近の研究では、複雑なトラフィックパターンを学習して未知の攻撃の特定に役立つ深層学習が探究されている。

ネットワーク型 IDS は人工ニューラルネットワーク（ANN）と組み合わせることもできる。ANN は隠れ層と非線形モデリングによって非常に大量のデータを分析できるが、時間がかかる。ANN ベースの IDS は誤りから学習して攻撃を予測し、早期警戒システムを支えることができる。4つのカテゴリ（サービス拒否、プローブ、リモートからローカル、ユーザーからルート）にわたる24のネットワーク攻撃を対象とした研究では、平均検知・分類率が99.9%と報告された。統計的なアノマリ型の検知では、マシューズ相関係数を用いて不正なトラフィックを識別するアンサンブルモデルが99.73%の精度に達している。

Gartner は、アノマリ型 IDS と呼べるものの新しい種類を、ユーザー・エンティティ行動分析（UEBA）とネットワークトラフィック分析（NTA）とみなしている。NTA は、悪意ある内部者や、ユーザーのマシンやアカウントを侵害した標的型の外部攻撃に対処するもので、Gartner は、一部の組織がより従来型の IDS よりも NTA を選んでいると指摘している。

## 侵入検知と侵入防止

IDS は、侵入の疑いが生じた後にそれを記述し、アラームを発する。侵入を阻止することは、監視システムには求められても期待されてもいない。対応も行えるシステムは、侵入防止システム（IPS）、または侵入検知・防止システム（IDPS）と呼ばれる。これらは IDS の拡張とみなされている。どちらもネットワークトラフィックやシステムの活動を監視して悪意ある活動を探すが、IPS はインラインに配置され、侵入を能動的に阻止できる。すなわち、アラームの送信、悪意あるパケットの破棄、接続のリセット、問題の IP アドレスからのトラフィックの遮断を行う。

| IPS の種類 | 監視対象 |
| --- | --- |
| ネットワーク型（NIPS） | プロトコルの活動を分析することによるネットワーク全体 |
| 無線型（WIPS） | 無線ネットワークのプロトコルを分析することによる無線ネットワーク |
| ネットワーク行動分析（NBA） | 分散型サービス拒否攻撃、一部のマルウェア、ポリシー違反など、異常なフローを生む脅威を探すためのネットワークトラフィック |
| ホスト型（HIPS） | ホスト内で発生するイベントを分析することによる単一のホスト |

ほとんどの侵入防止システムは、3つの検知手法のいずれかを用いる。シグネチャ型、統計的アノマリ型（トラフィックを、そのネットワークにとって何が正常かを示す確立されたベースラインと比較する）、そしてステートフルプロトコル分析（観測されたプロトコルの状態を、あらかじめ定められた良性の活動のプロファイルと比較するもので、多くのリソースを必要とする）である。

## ファイアウォールとの違い

従来のネットワークファイアウォールは、静的なルールの集合を用いて接続を許可または拒否し、ネットワーク間のアクセスを制限して侵入を防ぐ。ネットワーク内部からの攻撃を知らせることはしない。IDS は侵入の疑いについてアラームを発し、システム内部から発生する攻撃も監視する。

## 配置

最も一般的な配置は、ネットワークの境界にあるファイアウォールの内側であり、これにより IDS はネットワークに入ってくるトラフィックを広く見渡せる。ファイアウォールの外側に配置された IDS は、主にインターネットからのノイズやポートスキャンなどのありふれた攻撃に対する防御となる。実際の侵害ではなく試みられた侵害を示すため、誤検知が減る。ネットワーク内部に配置された IDS は、内部での攻撃や不審な活動を明らかにする。ネットワーク内部のセキュリティを軽視すると、すでに侵入した攻撃者が自由に動き回れてしまうのに対し、イントラネットのセキュリティを強化すると、攻撃者が動き回ったり権限を昇格したりするのが難しくなる。

## 限界

- **誤報** — ソフトウェアのバグ、破損した DNS データ、漏れ出たローカルパケットに起因するノイズによって誤報率が非常に高くなることがあり、本物の攻撃が誤報に埋もれて見逃されることがある。
- **シグネチャの遅れ** — シグネチャのデータベースは常に更新する必要がある。シグネチャ型の IDS は、新しい脅威のシグネチャが適用されるまでその脅威を識別できない。
- **死角** — IDS は弱い識別・認証やネットワークプロトコルの弱点を補うことはできず、ほとんどの機器は暗号化されたパケットを処理せず、IP パケットのアドレスは偽装されうる。
- **IDS 自体の脆弱性** — NIDS はプロトコルを捕捉したとおりに分析するため、無効なデータや TCP/IP スタック攻撃など、ネットワークホストが脆弱であるのと同じプロトコルベースの攻撃によってクラッシュさせられうる。

## 回避手法

攻撃者が IDS を回避するために用いる単純な手段には、パケットの断片化、デフォルト以外のポートでのプロトコルの実行、多数の攻撃者による低帯域幅のスキャンの連携、アドレスの偽装やプロキシを経由した攻撃の中継、そして IDS が想定するパターンに一致しなくなるよう攻撃データをわずかに変えることがある。

## 歴史

| 年 | 進展 |
| --- | --- |
| 1980年 | 国家安全保障局（NSA）の James Anderson が、最初期の予備的な IDS の概念を記述した。ユーザーのアクセス、ファイルのアクセス、システムイベントのログなどの監査証跡を管理者が確認するのを助けるツール群である |
| 1986年 | Dorothy E. Denning が Peter G. Neumann の協力を得て、後の多くのシステムの基礎となった IDS のモデルを発表した。これは異常検知に統計を用いるもので、SRI International における Intrusion Detection Expert System（IDES）につながった。IDES はルールベースのエキスパートシステムと統計的な異常検知を組み合わせたものである。NSA も Rebecca Bace のもとで IDS の研究移転プログラムを開始した |
| 1987年 | Fred Cohen が、あらゆる場合に侵入を検知することは不可能であり、必要なリソースは利用量とともに増大すると指摘した |
| 1988〜1991年 | MIDAS、Haystack、Wisdom & Sense、Time-based Inductive Machine（ユーザーのパターンの帰納学習による異常検知）、Network Security Monitor、DIDS、NADIR などのシステムが開発された。これらは統計的な異常検知、エキスパートシステム、帰納学習などのアプローチを用いていた |
| 1993年 | SRI が IDES の後継として Next-generation Intrusion Detection Expert System（NIDES）を開発した。 |
| 1998年 | ローレンス・バークレー国立研究所が Bro を発表した。パケットスニファ APE は Snort と改名され、その後30万人を超えるアクティブユーザーをもつ、世界で最も広く使われる IDS/IPS となった |
| 2015年 | たとえば IoT（モノのインターネット）アプリケーション向けに、システムオンチップ上で機械学習を適用するアノマリ型の検知エンジンが提案された |

IDES は、既知の侵入に対するルールベースのエキスパートシステムと、ユーザー、ホストシステム、ターゲットシステムのプロファイルに基づく統計的な異常検知の構成要素とを組み合わせていた。IDES を記述した論文の著者である Teresa F. Lunt は、3つ目の構成要素として人工ニューラルネットワークを加え、3つすべてが解決器（resolver）に報告する構成を提案した。
