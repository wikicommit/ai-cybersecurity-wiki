データポイズニングとは、[[DefinedTerm/adversarial-machine-learning|敵対的機械学習]]における攻撃の一つで、出力の誤りを増やすよう設計されたデータでモデルの訓練データセットを汚染するものである。学習アルゴリズムは訓練データセットによって形作られるため、ポイズニングによって事実上アルゴリズムを再プログラムでき、それが悪意をもって行われる可能性もある。すでに訓練されたモデルへの入力を操作する[[DefinedTerm/evasion-attack|回避攻撃]]とは異なり、ポイズニングはモデルが学習するデータに作用する。訓練データポイズニングは [[DefinedTermSet/owasp-top-10-for-llm-applications|OWASP Top 10 for LLM Applications]] のバージョン1.1の項目 LLM03 であり、このリストの2025年版では、対応する項目は LLM04:2025「Data and Model Poisoning」である。

## 懸念される理由

特に懸念されているのは、コンテンツ推薦や自然言語モデルに用いられるデータなど、ユーザー生成の訓練データである。偽アカウントが至るところに存在することはポイズニングの多くの機会をもたらす。報道によれば Facebook は年間約70億の偽アカウントを削除しており、ポイズニングは産業応用における最大の懸念事項であると報告されている。ソーシャルメディアでは、偽情報キャンペーンが推薦アルゴリズムやモデレーションアルゴリズムを偏らせ、特定のコンテンツを他のコンテンツより優先させようとする。

## 形態

| 形態 | 内容 |
| --- | --- |
| バックドア攻撃 | ポイズニングの特殊なケースで、画像、音声、動画、テキスト内の小さな欠陥など、特定のトリガーを含む入力に対する特定の振る舞いをモデルに教え込む |
| 運用中のポイズニング | [[DefinedTerm/intrusion-detection-system\|侵入検知システム]]のように、運用中に収集したデータで再訓練されるシステムは、悪意あるサンプルを注入されることでポイズニングされ、その後の再訓練が妨害されうる |
| テキストから画像を生成するモデルのポイズニング | テキストから画像を生成するモデルにポイズニング手法を適用すると、その出力が変わる。アーティストは、著作権のある作品や芸術的スタイルを模倣から守るためにこれを利用している |
| 意図しないポイズニング | モデルが合成データで訓練される場合、モデル崩壊（model collapse）によって攻撃者なしにポイズニングが起こりうる |

## 事例

- **Nightshade** — シカゴ大学の研究者らが2023年に公開したデータポイズニングフィルタ。視覚芸術家が自分の作品に適用することで、テキストから画像を生成するモデルのデータセットを破損させるためのものである。そうしたモデルは通常、画像の作成者の同意なしにインターネットからデータを収集している。
- **言語モデルのバックドア** — AI Security Institute、Anthropic、Alan Turing Institute の研究者らによる2025年の研究は、言語モデルにバックドアを仕込むのに必要な汚染文書の数が、試験したモデルサイズや訓練セットのサイズにかかわらずほぼ一定であることを見出した。研究者らは6億から130億パラメータのモデルを60億から2,600億トークンで事前訓練した。どの規模でも、250件の汚染文書を加えるだけで、トリガーフレーズに対してモデルに意味不明な文字列を出力させるサービス拒否型のバックドアを仕込むのに十分であった。130億パラメータのモデルでは、それらの文書は訓練トークンの約0.00016%であった。著者らは、そうしたバックドアが現実的な事後訓練を経ても残るかどうかはこの研究では確認されていないと述べた。また共著者の Vasilios Mavroudis は、特定のユーザー層に対してモデルの有用性を選択的に下げるバックドアは、あからさまな故障よりも検出が難しい可能性があると示唆した。

## 大規模言語モデルのアプリケーションにおいて

OWASP Top 10 for LLM Applications のバージョン1.1（2023年）は、訓練データポイズニングを、モデルのセキュリティ、有効性、倫理的な振る舞いを損ないうる脆弱性、バックドア、バイアスを持ち込むために、事前訓練データ、あるいはファインチューニングや埋め込みに用いられるデータを操作することと定義している。これは3つの段階にわたる。

| 段階 | リストによる説明 |
| --- | --- |
| 事前訓練 | タスクまたはデータセットでモデルを訓練すること |
| ファインチューニング | 厳選されたデータセット（通常は入力例と望ましい出力の組）で訓練することにより、訓練済みのモデルをより狭い主題や目的に適応させること |
| 埋め込み | カテゴリデータ（多くはテキスト）を、言語モデルの訓練に使える数値ベクトルに変換すること |

このリストは、訓練データの改ざんはモデルが正しい予測を行う能力に影響するため、データポイズニングを完全性に対する攻撃と呼んでいる。外部のデータソースはより高リスクだとみなしている。モデルの作成者はそれらを管理できず、バイアス、改ざんされた情報、不適切なコンテンツが含まれていないと確信できないからである。汚染された情報はユーザーに届いたり、性能の低下、下流のソフトウェアの悪用、評判の毀損を引き起こしたりしうる。ユーザーが出力を信用していなくても、そのリスクは残る。

リストが挙げるこの脆弱性の例には、悪意ある主体や競合他社がモデルの事前訓練データ、ファインチューニングデータ、埋め込みを狙って不正確または悪意ある文書を作成することがあり、その例示として split-view ポイズニングと frontrunning ポイズニングを挙げている。他の例として、改ざんされた、偏った、あるいは有害なコンテンツが訓練に直接注入され、後の出力で返されること、ユーザーが知らずに機密情報や専有データを訓練に投入してしまうことがある。リストはまた、LLM アプリケーションへのクライアントの入力が十分なサニタイズやフィルタリングなしにモデルの訓練に用いられる場合、プロンプトインジェクションがポイズニングの攻撃ベクトルになりうると指摘している。

## OWASP リストの2025年版において

2025年版の項目 LLM04:2025「Data and Model Poisoning」は、データポイズニングは脆弱性、バックドア、バイアスを持ち込むために事前訓練、ファインチューニング、埋め込みのデータが操作されたときに起こり、モデルのセキュリティ、性能、倫理的な振る舞いを損ない、有害な出力や能力の低下につながりうると述べている。バージョン1.1と同様に、データポイズニングを完全性に対する攻撃と呼び、未検証または悪意あるコンテンツを含みうる外部のデータソースを特に高リスクだとみなしている。

この項目は、モデルそのものについて2つの点を付け加えている。

- **共有モデルに潜むマルウェア** — 共有リポジトリやオープンソースのプラットフォームを通じて配布されるモデルは、データポイズニングを超えるリスクを抱えうる。たとえば悪意ある pickle 化によって埋め込まれたマルウェアは、モデルの読み込み時に有害なコードを実行しうる。
- **スリーパーエージェントとしてのバックドア** — ポイズニングによって、特定のトリガーが変化を引き起こすまでモデルの振る舞いをそのままにしておくバックドアが仕込まれることがある。項目は、これによってそうした変化のテストや検出が難しくなりうること、事実上モデルが「スリーパーエージェント」になる機会を生み出すことを指摘している。

この脆弱性の例として挙げられているのは、悪意ある主体が split-view データポイズニングや frontrunning ポイズニングなどの手法を使って訓練中に有害なデータを持ち込み、出力を偏らせること、攻撃者が有害なコンテンツを訓練プロセスに直接注入すること、ユーザーが対話の中で知らずに機密情報や専有情報を注入し、それが後の出力で露出しうること、未検証の訓練データ、そして資源へのアクセス制限の欠如によって安全でないデータが取り込まれることである。5つの攻撃シナリオ例には、攻撃者が訓練データの操作やプロンプトインジェクションを通じて出力を偏らせ、誤情報を広めること、競合他社が訓練用に改ざんした文書を作成すること、攻撃者がバックドアトリガーを仕込み、認証の回避、データの持ち出し、隠れたコマンドの実行への道を開きうることが含まれる。

この項目は、このリスクを MITRE ATLAS の技術 AML.T0018（Backdoor ML Model）と関連づけ、AI の完全性を確保するための戦略について NIST AI リスクマネジメントフレームワークを参照先として挙げている。

## 防御

モデルのアンサンブルは、回避攻撃に対しては効果がないものの、データポイズニング攻撃に対しては効果的であることが示されている。回避攻撃、ポイズニング攻撃、プライバシー攻撃に対して提案されているより広範な仕組みには、訓練データのサニタイズやバックドア検出アルゴリズムが含まれる。

OWASP リストのバージョン1.1は、LLM アプリケーション向けに次の予防策を挙げている。

- 訓練データ、特に外部データのサプライチェーンを、「Machine Learning Bill of Materials」（ML-BOM）による証明を通じて検証し、モデルカードを確認すること
- 事前訓練、ファインチューニング、埋め込みの各段階でデータソースの正当性を確認し、ユースケースごとに別々のモデルを訓練すること
- モデルが意図しないデータソースを収集できないよう、ネットワーク制御によってサンドボックス化すること
- 訓練データに対する厳格な審査や入力フィルタ、そしてファインチューニングの前に敵対的なデータを取り除くための、統計的な外れ値検出と異常検知によるデータのサニタイズ
- 連合学習、外れ値の影響を最小化する制約、敵対的訓練などの敵対的頑健性の手法
- 訓練中の損失の測定と、特定のテスト入力に対する訓練済みモデルの振る舞いの分析によるポイズニングの検出、偏った応答がしきい値を超えたときの監視と警告、人間による応答のレビュー、テスト中の LLM レッドチーム演習や脆弱性スキャン

2025年版の項目の予防・緩和戦略には次のものがある。

- OWASP CycloneDX や ML-BOM などのツールでデータの出所と変換を追跡し、モデル開発のあらゆる段階でデータの正当性を検証すること
- データベンダーを厳格に審査し、信頼できる情報源と照らしてモデルの出力を検証することで、ポイズニングの兆候を検出すること
- 未検証のデータソースへのモデルの露出を制限する厳格なサンドボックス化、敵対的なデータを除外するための異常検知、そしてモデルが意図しないデータソースにアクセスしないようにするインフラ上の制御
- ユースケースごとのモデルのファインチューニングに特定のデータセットを用いること
- データセットの変更を追跡して操作を検出するためのデータバージョン管理（DVC）
- ユーザーが提供した情報をベクトルデータベースに格納し、モデル全体を再訓練せずに調整できるようにすること
- レッドチームキャンペーンや、連合学習などの敵対的手法によってモデルの頑健性をテストし、データの摂動の影響を最小化すること
- 訓練損失を監視し、ポイズニングの兆候がないかモデルの振る舞いを分析し、しきい値を設けて異常な出力を検出すること
- 推論時に、検索拡張生成（RAG）やグラウンディングの手法を組み込んでハルシネーションのリスクを減らすこと
