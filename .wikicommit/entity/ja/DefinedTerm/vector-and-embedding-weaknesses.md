ベクトルと埋め込みの脆弱性とは、大規模言語モデル（LLM）で検索拡張生成（RAG）を用いるシステムにおけるセキュリティリスクである。ベクトルと埋め込みの生成・保存・検索の方法に潜む弱点は、意図的か否かを問わず悪意ある行為によって悪用され、有害なコンテンツの注入、モデル出力の操作、機微な情報へのアクセスにつながりうる。[[DefinedTermSet/owasp-top-10-for-llm-applications|OWASP Top 10 for LLM Applications]] の2025年版の項目 LLM08:2025「Vector and Embedding Weaknesses（ベクトルと埋め込みの脆弱性）」を構成する。この項目は RAG を、事前学習済みの言語モデルと外部の知識源を組み合わせ、ベクトルの仕組みと埋め込みを用いることで、LLM アプリケーションの応答の性能と文脈上の関連性を高めるモデル適応の手法として説明している。

## とりうる形態

| リスク | 内容 |
| --- | --- |
| 不正アクセスとデータ漏洩 | アクセス制御が不十分であったり整合していなかったりすると、機微な情報を含む埋め込みへの不正アクセスが可能になり、モデルが個人データ、専有情報、その他の機微なコンテンツを取得して開示してしまう。拡張の過程での著作物の無断使用や、データ利用ポリシーへの不準拠は、法的な影響をもたらしうる |
| コンテキスト間の情報漏洩とフェデレーションにおける知識の衝突 | マルチテナント環境で、複数の種類のユーザーやアプリケーションが一つのベクトルデータベースを共有している場合、ユーザー間やクエリ間でコンテキストが漏洩しうる。知識の衝突によるエラーは、複数の情報源からのデータが互いに矛盾する場合や、LLM が訓練で学習した内容を検索拡張による新しいデータで置き換えられない場合に起こる |
| 埋め込みの反転攻撃 | 攻撃者が脆弱性を突いて埋め込みを反転し、元の情報の相当量を復元して、データの機密性を損なう |
| [[DefinedTerm/data-poisoning\|データポイズニング]]攻撃 | 悪意ある者によって意図的に、あるいは意図せずに持ち込まれた汚染データは、内部関係者、プロンプト、データシーディング、検証されていないデータ提供者に由来しうるものであり、操作されたモデル出力につながる |
| 振る舞いの変化 | 検索拡張は、基盤モデルの振る舞いを意図せず変えてしまうことがある。事実の正確さや関連性は高まる一方で、感情的知性や共感といった側面が損なわれ、用途によってはモデルの有効性が下がる可能性がある |

## 事例シナリオ

項目は3つの攻撃シナリオの例を、それぞれの緩和策とともに挙げている。

- **データポイズニング** — 攻撃者が、RAG を用いて候補者を選考する求人応募システムに、指示を記した隠しテキスト（白い背景に白い文字など）を含む履歴書を提出する。後にシステムがその候補者の資格について問われると、LLM は隠された指示に従い、資格のない候補者をさらなる検討の対象として推薦してしまう。項目が示す緩和策は、書式を無視して隠されたコンテンツを検出するテキスト抽出ツールと、RAG のナレッジベースに追加する前にすべての入力文書を検証することである。
- **アクセス制御とデータ漏洩** — マルチテナント環境では、あるグループの埋め込みが、別のグループの LLM からのクエリに応じて取得され、ビジネス上の機微な情報が漏洩するおそれがある。緩和策は、権限を考慮したベクトルデータベースによって、許可されたグループだけがそれぞれ固有の情報にアクセスできるようにすることである。
- **振る舞いの変化** — 検索拡張の後、学生ローンの負債に押しつぶされそうになっているユーザーへのモデルの回答が、共感的な助言から純粋に事実だけを述べるものに変わる。項目は、修正後の応答は事実としては正しいが共感を欠いており、そのためアプリケーションの有用性が下がると述べている。緩和策は、RAG が基盤モデルの振る舞いに与える影響を監視・評価し、共感のような性質を保つよう拡張のプロセスを調整することである。

## 防止策

項目が挙げる防止と緩和の戦略は次のとおりである。

| 戦略 | 内容 |
| --- | --- |
| 権限とアクセス制御 | きめ細かなアクセス制御と、権限を考慮したベクトルおよび埋め込みのストアを用い、ベクトルデータベース内のデータセットを、異なる種類やグループのユーザーの間で論理的にもアクセスの面でも厳格に分離する |
| データの検証と情報源の認証 | 知識源に対する堅牢なデータ検証パイプライン、隠しコードやデータポイズニングがないかを調べるナレッジベースの完全性の定期的な監査、信頼でき検証済みの情報源からのデータのみの受け入れ |
| 結合と分類のためのデータのレビュー | 異なる情報源から結合したデータセットの徹底的なレビューと、アクセスレベルを制御しデータの不整合によるエラーを防ぐための、ナレッジベース内のデータのタグ付けと分類 |
| 監視とログ記録 | 不審な振る舞いを検知して速やかに対応するための、検索活動の詳細で改ざん不可能なログ |
