LLM による誤情報とは、大規模言語モデル（LLM）が生成する、信頼できそうに見える誤った情報や誤解を招く情報である。[[DefinedTermSet/owasp-top-10-for-llm-applications|OWASP Top 10 for LLM Applications]] の2025年版はこれを項目 LLM09:2025「Misinformation」として挙げ、こうしたモデルに依存するアプリケーションにとっての中核的な脆弱性であると説明している。セキュリティ侵害、評判の毀損、法的責任につながりうるからである。

## 原因

この項目によれば、誤情報の主要な原因の一つはハルシネーション、すなわち LLM が正確に見えるが捏造された内容を生成することである。ハルシネーションは、LLM が内容を本当に理解することなく、統計的なパターンを用いて訓練データの欠落を埋めるときに起こる。そのためモデルは、正しく聞こえるがまったく根拠のない回答を生成することがある。原因はハルシネーションだけではない。訓練データによって持ち込まれたバイアスや不完全な情報も一因となりうる。

関連する問題として過度の依存（overreliance）がある。これは、ユーザーが LLM の生成したコンテンツを過度に信頼し、その正確さを検証しないときに起こる。この項目は、ユーザーが十分な精査なしに誤ったデータを重要な意思決定やプロセスに組み込んでしまうおそれがあるため、過度の依存は誤情報の影響を悪化させると述べている。

## よくある例

この項目は、このリスクのよくある例を4つ挙げている。

| 例 | 起こること | 項目が挙げる事例 |
| --- | --- | --- |
| 事実の不正確さ | モデルが誤った記述を生成し、ユーザーが誤った情報に基づいて意思決定してしまう | Air Canada のチャットボットが旅行者に誤情報を提供し、業務上の混乱と法的な問題を招いた。その結果、同社は訴訟で敗訴した |
| 根拠のない主張 | モデルが根拠のない断定を生成する。医療や法的手続きのような機微な文脈では特に有害となりうる | ChatGPT が架空の判例をでっち上げ、法廷で重大な問題を招いた |
| 専門性の偽り | モデルが複雑なトピックを理解しているかのような錯覚を与え、その専門性の水準についてユーザーを誤らせる | チャットボットが健康に関する問題の複雑さを偽って伝え、不確実性のないところに不確実性があると示唆したことで、裏付けのない治療法がまだ議論の途上にあるとユーザーに信じ込ませていたことが判明した |
| 安全でないコードの生成 | モデルが安全でない、あるいは存在しないコードライブラリを提案し、それがソフトウェアシステムに組み込まれると脆弱性を持ち込みうる | LLM が安全でないサードパーティのライブラリを提案し、検証なしに信頼するとセキュリティリスクにつながる |

## 攻撃シナリオの例

この項目は2つのシナリオを説明している。1つ目では、攻撃者が人気のコーディングアシスタントを試して、それらがよくハルシネーションで生み出すパッケージ名を見つけ、その名前で悪意あるパッケージを広く使われているリポジトリに公開する。アシスタントの提案に頼る開発者は知らずにそのパッケージを組み込み、攻撃者は不正アクセスを得たり、悪意あるコードを注入したり、バックドアを仕込んだりする。

2つ目では、ある企業が十分な精度を確保しないまま医療診断用のチャットボットを提供する。チャットボットの質の低い情報が患者に害を与え、その企業は損害賠償訴訟で敗訴する。この項目は、この安全性とセキュリティの破綻には悪意ある攻撃者は必要なかったと指摘している。それは LLM システムの監督と信頼性の不足から生じたものであり、それでも企業は評判上および財務上の損害にさらされた。

## 予防と緩和

この項目は8つの戦略を挙げている。

| 戦略 | 内容 |
| --- | --- |
| 検索拡張生成（RAG） | 応答の生成中に、信頼できる外部データベースから関連性があり検証済みの情報を取得し、出力の信頼性を高めてハルシネーションを緩和する |
| モデルのファインチューニング | ファインチューニングや埋め込みによって出力の質を高める。パラメータ効率的チューニング（PET）や思考の連鎖（chain-of-thought）プロンプティングなどの手法が誤情報の削減に役立ちうる |
| 相互検証と人間による監督 | ユーザーに出力を信頼できる外部の情報源と照合するよう促し、重要な情報や機微な情報については人間による監督とファクトチェックを実施する。確認者には、AI が生成したコンテンツへの過度の依存を避けるよう訓練を施す |
| 自動検証の仕組み | 特に重大な結果を伴う環境で、主要な出力を自動的に検証するツールとプロセス |
| リスクコミュニケーション | 誤情報の可能性を含め、LLM が生成したコンテンツのリスクと起こりうる害を特定し、ユーザーに明確に伝える |
| セキュアコーディングの慣行 | 誤ったコードの提案によって脆弱性が組み込まれるのを防ぐ慣行 |
| ユーザーインターフェースの設計 | コンテンツフィルタ、AI が生成したコンテンツの明確なラベル付け、信頼性と正確さの限界に関する情報、想定される利用分野の具体的な制限など、責任ある利用を促す API とインターフェース |
| 訓練と教育 | LLM の限界、生成されたコンテンツを独立に検証することの重要性、批判的思考の必要性についてユーザーを訓練し、必要に応じて分野に特化した訓練を行う |
