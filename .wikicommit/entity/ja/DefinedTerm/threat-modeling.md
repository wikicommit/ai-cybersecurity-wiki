脅威モデリングとは、構造上の脆弱性や適切な保護策の欠如といった潜在的な脅威を特定・列挙し、対策や管理策に優先順位を付けるプロセスである。システムの性質、想定される攻撃者のプロファイル、最も可能性の高い攻撃ベクトル、最も攻撃されやすい資産を踏まえて、どの管理策や防御策を組み込む必要があるかについての体系的な分析を防御側にもたらす。「自分はどこが最も攻撃に対して脆弱か」「最も関連性の高い脅威は何か」「これらの脅威から身を守るために何をする必要があるか」といった問いに答えるものである。

## 起源

1960年代初頭に共有コンピューティングが登場して間もなく、私利のためにセキュリティ上の脆弱性を悪用する方法を探る者が現れ始め、エンジニアやコンピュータ科学者はほどなく情報技術システムのための脅威モデリングの概念を開発し始めた。

| 年 | 出来事 |
| --- | --- |
| 1977 | クリストファー・アレグザンダーが建築パターンの概念を初めて提示し、初期の技術中心の脅威モデリング手法はこれに基づいた |
| 1988 | ロバート・バーナードが IT システムの攻撃者の最初のプロファイルを開発し、適用した |
| 1994 | エドワード・アモローソが著書 *Fundamentals of Computer Security Technology* で、決定木の図に基づく「脅威ツリー」を提唱した。脅威ツリーは、IT システムに対する潜在的な脅威がどのように悪用されうるかを図式的に表す |
| 1998 | ブルース・シュナイアーが攻撃ツリーを用いたサイバーリスクの分析を発表した。攻撃ツリーでは攻撃者の目標が「ルートノード」、それを達成しうる手段が「リーフノード」となる |
| 1999 | Microsoft のローレン・コーンフェルダーとプラエリット・ガーグが、Microsoft Windows の開発環境に関連する攻撃を検討するためのモデルである STRIDE を開発した |
| 2003 | 組織のリスク管理に焦点を当てた運用中心の手法である OCTAVE（Operationally Critical Threat, Asset, and Vulnerability Evaluation）が導入された |
| 2004 | フランク・スウィダースキーとウィンドウ・スナイダーの著書 *Threat Modeling*（Microsoft Press）が、脅威モデルを用いてセキュアなアプリケーションを作るという概念を展開した |
| 2014 | ライアン・スティリオンズが、検知成熟度レベル（Detection Maturity Level、DML）モデルにおいて、サイバー脅威を異なる意味的レベルで表現することを提案した |
| 2020 | 脅威モデリングの権威たちが、すべての脅威モデリング実践者が知り従うべき中核的な価値観と原則を示す Threat Modeling Manifesto（脅威モデリング宣言）を公表した |
| 2024 | 同じ著者たちが続いて、脅威モデリングの実践のための能力の目録である Threat Modeling Capabilities 文書を公表した |

脅威ツリーとは独立に、NSA と DARPA は、IT システムに対する特定の攻撃がどのように実行されうるかを構造化された図で表す手法に取り組み、その成果は「攻撃ツリー」と呼ばれた。

DML モデルにおいて、攻撃とは、特定の目標とそれを達成するための戦略を持つ特定の攻撃者によって引き起こされる、脅威シナリオの具体化である。目標と戦略は最も高い意味的レベルにあり、戦術・技術・手順（TTP）は中間に、攻撃者のツール、ホストおよびネットワークのアーティファクト、そして最後に IP アドレスのようなアトミックな指標が最も低いレベルにある。現在の [[DefinedTerm/security-information-and-event-management|SIEM]] ツールは通常、最も低いレベルの指標しか提供しないため、より高いレベルの脅威指標を提供する SIEM ツールが求められている。

## 実施方法

IT に関するあらゆる脅威モデリングのプロセスは、分析を助けるために要素に分解した、アプリケーション、インフラストラクチャ、またはその両方の視覚的な表現を作ることから始まる。その表現を用いて潜在的な脅威を特定・列挙する。その後リスクをどう分析し、脅威にどう優先順位を付け、緩和のための管理策をどう列挙するかは、用いる手法によって異なる。アプローチは、使用中のシステム、攻撃者、資産のいずれかに焦点を当てることができる。

ほとんどのアプローチはデータフロー図（DFD）を用いる。DFD は1970年代に、アプリケーションによってデータがどのように流れ、インフラストラクチャによってどのように保存・操作されるかをシステムエンジニアが高いレベルで伝えるために開発された。DFD は伝統的に、データフロー、データストア、プロセス、インタラクタの4つの記号を用いてきたが、2000年代初頭に、脅威モデリングにより役立つよう5つ目の記号として信頼境界が追加された。システムをこれら5つの要素に分解したら、セキュリティの専門家は、特定された脅威の侵入点それぞれを既知のすべての脅威カテゴリーと照らし合わせて検討し、その後、緩和のための管理策を列挙するか、さらなる分析を行う。

## 手法

脅威モデリングの実践は手法から生まれ、多くの手法が利用できる。脅威モデリングは典型的には、資産中心、攻撃者中心、ソフトウェア中心、価値およびステークホルダー中心、ハイブリッドの5つのアプローチのいずれかを用いて実施されてきた。オンラインで公開されているコンテンツの量から判断すると、最もよく知られているのは以下のものである。

| 手法 | 概要 |
| --- | --- |
| STRIDE | なりすまし（Spoofing）、改ざん（Tampering）、否認（Repudiation）、情報漏洩（Information disclosure）、サービス拒否（Denial of service）、権限昇格（Elevation of privilege）の頭字語。単純なプロンプトやチェックリストとして使うことも、STRIDE per element のようなより構造化されたアプローチの中で使うこともできる。Microsoft が開発・公開したアプローチの一つであり、「Microsoft の」手法と言う場合は一般に STRIDE とデータフロー図を指す |
| PASTA（Process for Attack Simulation and Threat Analysis） | コンプライアンス上の問題やビジネス分析を考慮しつつ、ビジネス目標と技術要件を整合させるための、7段階からなるリスク中心の手法。動的な脅威の特定・列挙・スコアリングを目指し、防御側が資産中心の緩和戦略を立てるための攻撃者中心の視点を与える |
| ハイブリッド脅威モデリング手法（The Hybrid Threat Modeling Method） | 研究者たちが、SQUARE、Security Cards、Personae Non Gratae など、異なる手法の長所を組み合わせるために作成した |

## ツール

| ツール | 説明 |
| --- | --- |
| Microsoft Threat Modeling Tool（旧称 SDL Threat Modeling Tool） | 無料。DFD に基づき、STRIDE の分類を用いて脅威を特定する。主に汎用的な用途を想定している |
| IriusRisk | コミュニティ版と商用版がある。カスタマイズ可能な質問票とリスクモデルのライブラリを用いて、システム開発ライフサイクル全体を通じて生きた脅威モデルを維持し、自動化のために他のツールと連携する |
| securiCAD（foreseeti） | 企業のサイバーセキュリティ管理向け。現在および将来の IT アーキテクチャに対して自動化された攻撃シミュレーションを行い、リスクを定量化する |
| SD Elements（Security Compass） | 自動化された脅威モデリングを備えたソフトウェアセキュリティ要件管理プラットフォーム。短い質問票から脅威が生成され、対策は開発者のタスクとなる |
| [[Organization/owasp\|OWASP]] Threat Dragon | セキュアな開発ライフサイクルの一環として脅威モデル図を作成する。Threat Modeling Manifesto に従い、Web アプリケーションまたはデスクトップアプリケーションとして動作し、STRIDE、LINDDUN、CIA、DIE、PLOT4ai をサポートする |
| OWASP pytm | 初の Threat-Model-as-Code ツールとされる Python 的なフレームワーク。Python で定義したシステムを、DFD、シーケンス図、そのシステムに対する脅威の一覧に変換できる |

## IT 以外への応用

脅威モデリングは、車両や、ビルおよびホームオートメーションにも適用されている。そこでは、居住者の移動プロファイル、勤務時間、健康状態に関する情報といったセキュリティとプライバシーへの脅威が、物理的またはネットワーク経由の攻撃とあわせてモデル化される。こうした攻撃は、スマートビルのセンサー（居住者を監視するため）やアクチュエーター（ドアを解錠するため）を利用しうる。

自動車については、UN R155 がリスクアセスメントで考慮する必要のある少なくとも69の攻撃ベクトルを特定している。上記のいずれのフレームワークを用いてもよく、適合性の推定には ISO/SAE 21434 を用いることができる。デジタル要素を含む機器の製造者にそれをセキュアにすることを求めるサイバーレジリエンス法（Cyber Resilience Act）のもとでは、機械指令に基づいて製造される農業機械やオフロード機械の製造者は、ISO/DIS 24882 の指針を参考に上記のいずれのフレームワークを用いても、適合性を推定できる。

脅威モデリングと同様に、リスクアセスメントや脅威攻撃モデリングは、いじめっ子のようなリスクに対処するために日常生活の中で非公式に用いることができ、古代から軍事的な防衛準備の優先順位付けに用いられてきた。
