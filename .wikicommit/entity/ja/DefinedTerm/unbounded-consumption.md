無制限の消費とは、大規模言語モデル（LLM）のアプリケーションが、ユーザーに過剰かつ制御されない推論の実行を許してしまうときに生じる脆弱性であり、サービス拒否（DoS）、経済的損失、モデルの窃取、サービス品質の低下といったリスクにつながる。[[DefinedTermSet/owasp-top-10-for-llm-applications|OWASP Top 10 for LLM Applications]] の2025年版の項目 LLM10:2025「Unbounded Consumption（無制限の消費）」である。

## 対象とする範囲

この項目は推論から説明を始める。推論とは、LLM が学習したパターンと知識を適用して、入力されたクエリやプロンプトから応答や予測を生成するプロセスであり、項目はこれを LLM の重要な機能と呼んでいる。項目によれば、サービスを妨害する攻撃、標的の財務資源を枯渇させる攻撃、モデルの振る舞いを複製して知的財産を盗む攻撃は、いずれも成功するためにこの共通の種類の脆弱性に依存している。LLM は、特にクラウド環境において計算需要が高いため、リソースの悪用や不正な利用に対して脆弱である。

## よくある例

項目はこの脆弱性のよくある例を7つ挙げている。

| 例 | 攻撃者が行うこと | 項目が述べる影響 |
| --- | --- | --- |
| 可変長入力の大量送信 | 処理の非効率性を突き、長さの異なる多数の入力で LLM に過負荷をかける | リソースを枯渇させ、システムを応答不能にしうる |
| ウォレット拒否（Denial of Wallet、DoW） | クラウドベースの AI サービスの従量課金モデルを突き、大量の処理を発生させる | 提供者に持続不可能な財務負担を負わせ、財務破綻の危険をもたらす |
| 継続的な入力オーバーフロー | LLM のコンテキストウィンドウを超える入力を継続的に送る | 計算資源の過剰な使用、サービス品質の低下、運用の妨害 |
| リソース集約的なクエリ | 複雑なシーケンスや入り組んだ言語パターンを含む、異常に負荷の高いクエリを送る | システムリソースを消耗させ、処理を長引かせ、システム障害の危険をもたらす |
| API を介したモデル抽出 | 慎重に作り込んだ入力とプロンプトインジェクションの手法でモデルの API に問い合わせ、部分的なモデルを複製したりシャドーモデルを作ったりするのに十分な出力を集める | 知的財産の窃取と、元のモデルの完全性の毀損 |
| 機能的なモデル複製 | 標的のモデルを使って合成訓練データを生成し、それを用いて別の基盤モデルをファインチューニングする | 機能的に同等なものを作り、従来のクエリベースの抽出を回避する |
| サイドチャネル攻撃 | LLM の入力フィルタリングの手法を悪用する | モデルの重みとアーキテクチャの情報を収集する |

項目にある6つの攻撃シナリオの例も同じ方向に沿っている。メモリと CPU の使用量を押し上げる異常に大きな入力、正当なユーザーがサービスを利用できなくなるほどの大量のリクエスト、最も計算コストの高い処理を引き起こすよう作り込んだ入力、従量課金の料金体系を突く過剰な処理、API を通じた機能的なモデル複製、そして LLM の入力フィルタリングとプリアンブルを回避してサイドチャネル攻撃を行い、攻撃者の管理下にあるリモートのリソースへモデルの情報を送ることである。

## 防止と緩和

項目は15の戦略を挙げている。保護する対象ごとにまとめると次のとおりである。

| 懸念 | 項目が挙げる戦略 |
| --- | --- |
| リソース使用の制限 | 入力が妥当なサイズ上限を超えないようにする厳格な入力検証、送信元エンティティごとのレート制限とユーザークォータ、リソース割り当ての動的な監視と管理、リソース集約的な処理のタイムアウトとスロットリング、高負荷時のグレースフルデグラデーション、キューに入れられる処理と処理総数の上限、および動的なスケーリングと負荷分散 |
| 検知 | リソース消費の包括的なログ記録、監視、[[DefinedTerm/anomaly-detection\|異常検知]] |
| モデルの保護 | API 応答における `logit_bias` と `logprobs` の公開の制限または難読化、LLM の出力に透かしを埋め込み不正利用を検知する透かしフレームワーク、敵対的なクエリや抽出の試みを検知・緩和するための敵対的ロバスト性訓練、既知のグリッチトークンを出力がコンテキストウィンドウに追加される前に除去するフィルタリング |
| アクセスとガバナンス | ネットワークリソース、内部サービス、API への LLM のアクセスのサンドボックス化、モデルリポジトリと訓練環境に対する、ロールベースアクセス制御（RBAC）や最小権限の原則を含む強力なアクセス制御、本番モデルのための一元化された ML モデルのインベントリまたはレジストリ、ガバナンス・追跡・承認のワークフローを備えた自動化された MLOps デプロイメント |

項目は特にサンドボックス化を重要なものとして取り上げている。サンドボックス化は内部関係者によるリスクと脅威を包含し、LLM アプリケーションがデータやリソースにどこまで到達できるかを統制するため、サイドチャネル攻撃を緩和または防止するための極めて重要な管理策となる。

## 関連するフレームワーク

項目は無制限の消費を次のものと関連付けている。

- MITRE CWE-400「Uncontrolled Resource Consumption（制御されないリソース消費）」

- OWASP Machine Learning Security Top Ten の ML05:2023 Model Theft、API4:2023 Unrestricted Resource Consumption、およびリソース管理に関する OWASP のセキュアコーディングのガイダンス
