Model Context Protocol（MCP）は、大規模言語モデル（LLM）などの人工知能システムが外部のツール、システム、データソースと連携し、データを共有する方法を標準化するために、Anthropic が2024年11月に発表したオープン標準かつオープンソースのフレームワークである。ファイルの読み取り、関数の実行、文脈的なプロンプトの処理のための標準化されたインターフェースを提供する。発表後、OpenAI や Google DeepMind を含む主要な AI プロバイダーに採用され、2025年12月には Anthropic が Linux Foundation 傘下の基金である Agentic AI Foundation に寄贈した。以下で述べるとおり、MCP を通じてモデルにツールへのアクセスを与えたことで、モデルが[[DefinedTerm/prompt-injection|プロンプトインジェクション]]や MCP ソフトウェア自体の欠陥にさらされてきたため、MCP はセキュリティ上重要である。

## 起源と目的

Anthropic は MCP を、AI アシスタントをコンテンツリポジトリ、業務管理ツール、開発環境といったデータシステムに接続するためのオープン標準として発表した。このプロトコルは Anthropic のエンジニアである David Soria Parra と Justin Spahr-Summers によって作られ、情報のサイロ化とレガシーシステムの問題に対処するよう設計された。MCP 以前は、開発者がデータソースやツールごとに個別のコネクタを構築しなければならないことが多く、Anthropic はこれを「N×M」のデータ統合問題と表現した。OpenAI の2023年の「function-calling」API や ChatGPT のプラグインフレームワークといった以前の手法も同様の問題を解決していたが、ベンダー固有のコネクタを必要とした。MCP は Language Server Protocol（LSP）のメッセージフローの考え方を再利用している。

## 仕組み

このプロトコルは3つの役割を区別する。

| 役割 | 何をするか |
| --- | --- |
| MCP ホスト | 典型的には、LLM とやり取りし、1つ以上の MCP サーバーのサービスを必要とする AI エージェント。サーバーごとに専用の MCP クライアントを作成する |
| MCP クライアント | ホストに代わって1つの MCP サーバーと通信する。クライアントとホストは通常同じマシン上で動作する |
| MCP サーバー | 1つ以上のツール（たとえばデータベースへのアクセス、計算機、コードやリポジトリへのアクセス）やリソース（たとえば FAQ のような文書）を提供する。ローカルの場合もリモートの場合もある |

クライアントはサーバーに、提供するツールとリソースの一覧を要求し、サーバーは各ツールの機能を自然言語で説明したものと、それを呼び出す際に期待される形式を返す。この情報は LLM に与えられる。LLM がいずれかのツールを必要とすると、ホストは該当するクライアントにその呼び出しを指示する。サーバーが処理を実行して結果を返し、ホストはその結果を LLM との会話に注入する。クライアントとサーバーは JSON-RPC 2.0 メッセージを用いて通信する。

このプロトコルは、Python、TypeScript、C#、Java などの言語向けのソフトウェア開発キット（SDK）とともに、サーバー実装の例を添えて公開された。用途には、構造化データベースへの平易な言語による問い合わせや、IDE 内の AI コーディングアシスタント、Replit のようなコーディングプラットフォーム、Sourcegraph のようなコードインテリジェンスツールに、プロジェクトの文脈へのリアルタイムのアクセスを与えることが含まれる。mcp-ui を基盤とする公式拡張機能である MCP Apps は、MCP サーバーから Claude や ChatGPT のようなホストアプリケーションへ、ダッシュボード、フォーム、データ可視化といったインタラクティブなユーザーインターフェースを配信する方法を標準化している。一方、基本仕様はテキストと構造化データに限定されている。

### 2026年7月の改訂

2026年7月28日、MCP のメンテナーは仕様の大規模な改訂を確定させた。Anthropic の技術スタッフである David Soria Parra は、これを認可機能の追加以来、このプロトコルにとって最も大きな変更だと述べた。この改訂は次のことを行う。

- プロトコルレベルのセッション追跡を廃止し、MCP をプロトコル層でステートレスにする。プロトコルのバージョン、クライアントの識別情報、機能は、代わりに各リクエストの `_meta` パラメータで運ばれ、MCP のリクエストモデルを Anthropic の Claude Messages API のそれに近づける。
- 利用が限られていたいくつかの機能を非推奨とする。これには *sampling*（サーバーがクライアントのモデルに補完を要求できるようにする機能）や *roots*（クライアントが関連するファイルシステム上の場所をサーバーに示せるようにする機能）が含まれる。非推奨とされた機能は少なくとも12か月間は引き続き動作する。
- 長時間実行される処理のための Tasks 機能など、以前は中核だった一部の機能を、基本プロトコルからオプションの拡張機能へ移す。

すべての変更に後方互換性があるわけではない。新しい改訂を実装したサーバーは、互換性レイヤーなしでは古いクライアントと相互運用できない場合がある。

## 普及

| 時期 | 出典が報じている内容 |
| --- | --- |
| 2025年3月 | OpenAI が MCP を正式に採用した。すでに ChatGPT デスクトップアプリを含む自社製品全体に MCP を統合していた |
| 2025年9月 | OpenAI が ChatGPT アプリに MCP のサポートを追加し、ChatGPT 内からのサードパーティによるアクセスを可能にした |
| 2025年12月 | Anthropic が MCP を、Anthropic、Block、OpenAI が共同で設立した Linux Foundation 傘下の指定基金である Agentic AI Foundation（AAIF）に寄贈した。同月後半、Anthropic は、エージェントが必要に応じて読み込むタスク固有の指示とリソースをパッケージ化するための関連オープン標準である Agent Skills も公開した |
| 2026年4月 | AAIF がニューヨーク市で MCP Dev Summit North America を開催し、約1,200人が参加した。Salesforce の Headless 360 プラットフォームが、顧客とエージェントのやり取りを MCP 経由でルーティングし始めた |

MCP は Microsoft Semantic Kernel や Azure OpenAI とも統合でき、MCP サーバーは Cloudflare にデプロイすることもできる。2026年半ばまでに、10,000を超える MCP サーバーが本番環境にデプロイされたと報じられている。The Verge は、MCP が、文脈を認識し多様な情報源を活用できる AI エージェントへの高まる需要に応えるものだと報じた。また MCP は、API を記述するための類似の仕様である OpenAPI になぞらえられている。

## セキュリティ上のリスクと脆弱性

MCP は、モデルがツール呼び出しをどう扱うかという点と、MCP ソフトウェア自体の両方で、セキュリティ上の脆弱性にさらされてきた。

**ツールポイズニング。** Invariant Labs は、AI モデルには読めるがユーザーには見えない MCP のツール説明に悪意のある指示を隠す「ツールポイズニング攻撃」について説明した。この弱点は、ツール説明が信頼できるという前提から生じる。出典によれば、これらの問題は MCP に固有のものではなく、LLM が信頼できない入力を伴うツールにアクセスできる場合にはいつでも起こりうる。ツールポイズニングは[[DefinedTerm/prompt-injection|プロンプトインジェクション]]の一形態である。

**MCP ソフトウェアの欠陥。**

| 脆弱性 | 影響を受けたソフトウェア | 何が可能になったか |
| --- | --- | --- |
| CVE-2025-6514（2025年7月に JFrog が公表。深刻度はクリティカル、CVSS 9.6） | MCP クライアントをリモートサーバーに接続するツールである mcp-remote。バージョン 0.0.5 から 0.1.15 が影響を受け、バージョン 0.1.16 で修正された | 悪意のあるサーバーがユーザーのマシン上で任意のコマンドを実行できた |
| CVE-2025-49596（ほぼ同時期に報告） | Anthropic の開発者向けツールである MCP Inspector | Inspector はデフォルトで認証を必要としなかったため、攻撃者はそれを使ってユーザーのコンピュータ上でコードを実行できた |

**仕様の変更。** その後、仕様にはセキュリティ要件が追加された。実装は OAuth 2.1 のセキュリティのベストプラクティスに従わなければならず、仕様のセキュリティガイダンスは MCP のプロキシサーバーにおける「混乱した代理（confused deputy）」のリスクを説明し、トークンのパススルーは禁止されていると定めている。米国国家安全保障局は、MCP の「急速な普及がそのセキュリティモデルの発展を上回っている」と述べている。
