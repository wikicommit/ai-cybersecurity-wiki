セキュリティ情報イベント管理（SIEM）は、セキュリティ情報管理（SIM）とセキュリティイベント管理（SEM）を組み合わせ、アプリケーションやネットワーク機器が生成するセキュリティアラートのリアルタイム分析を可能にする、コンピュータセキュリティの一分野である。SIEM システムはセキュリティオペレーションセンター（SOC）の中核をなし、そこでセキュリティインシデントの検知・調査・対応に用いられる。SIEM システムは多数のシステムからデータを収集・集約し、それによって組織は脅威から身を守りつつコンプライアンス要件を満たすことができる。

米国国立標準技術研究所（NIST）は、SIEM ツールを「情報システムの構成要素からセキュリティデータを収集し、そのデータを単一のインターフェースを通じて実用的な情報として提示する機能を提供するアプリケーション」と定義している。SIEM ツールはソフトウェア、ハードウェア、マネージドサービスのいずれの形でも実装できる。SIEM ツールはセキュリティイベントを記録し、医療保険の相互運用性と説明責任に関する法律（HIPAA）やペイメントカード業界データセキュリティ基準（PCI DSS）などの規制枠組みに対応するためのレポートを生成する。

## 起源と発展

SIEM という用語は、2005 年に Gartner のアナリストである Mark Nicolett と Amrit Williams によって導入された。SIEM はシステムロギングから発展したものである。システムロギングは当初、主にトラブルシューティングやデバッグに用いられていたが、オペレーティングシステムやネットワークが複雑化し、サイバー攻撃が高度化し、規制枠組みがリスクマネジメントフレームワーク（RMF）の中でセキュリティ管理策のロギングを義務づけ始めるにつれて、ログの監視はますます一般的になった。1970 年代後半からは作業部会が監査・監視プログラムを管理するための基準を定め、1990 年代後半から 2000 年代にかけて情報保証が成熟するにつれて、システムログを一元化する必要性が明らかになった。

この用語はその後、脅威インテリジェンスや振る舞い分析といった機能を含むように発展し、これによって SIEM ソリューションはゼロデイ脆弱性やポリモーフィック型マルウェアを含む複雑な脅威に対処できるようになった。現代の SIEM プラットフォームは、情報技術（IT）のソースだけでなく、生産・製造現場の制御技術（OT）からのデータも集約・正規化し、検知だけでなく対応も支援する。対応は手動でも自動でもよく、AI に基づく対応も含まれる。

SIEM は国家的なサイバーセキュリティの取り組みにも組み込まれている。重要インフラに対するランサムウェア攻撃の増加を受けて、米国のジョー・バイデン大統領が 2021 年 5 月 17 日に署名した大統領令 14028「国家のサイバーセキュリティの向上（Improving the Nation's Cybersecurity）」は、連邦政府のシステムにおけるインシデントの検知と報告を改善するために SIEM 技術の使用を義務づけ、監査ロギングやエンドポイント保護を含むさらなるロギング要件を定めた。

## セキュリティガイダンスにおける位置づけ

NIST SP 800-92『Guide to Computer Security Log Management』（2006 年 9 月）は、NIST リスクマネジメントフレームワークの中で何を監査可能にすべきかを示している。同文書は SIEM が広く普及する以前のもので、この用語を用いていない。FISMA、グラム・リーチ・ブライリー法、HIPAA、サーベンス・オクスリー法、PCI DSS、ISO 27001 など、いくつもの規制や標準が NIST のロギングに関するガイダンスを参照している。

SIEM ソリューションは通常、NIST SP 800-53 の次の 3 つの管理策の中心的なツールとなる。

| 管理策 | 対象 |
| --- | --- |
| AU-2 イベントモニタリング（Event Monitoring） | システムの監査と継続的な監視。機密性・完全性・可用性への影響度で分類される連邦政府のシステムには、5 つのロギング要件（AU-2 a〜e）がある。あらゆる操作をロギングすることも可能だが、ログの量が膨大になることと、実用的なデータが必要であることから、一般には推奨されない |
| SI-4 システムモニタリング（System Monitoring） | 不正アクセスを検知し、異常、マルウェア、潜在的な攻撃を追跡するためのシステムの監視。不審な活動を検知するためのハードウェアおよびソフトウェアの要件を含む |
| RA-10 脅威ハンティング（Threat Hunting） | 第 5 版（Revision 5）で追加された。従来の管理策をすり抜ける脅威を特定する能動的なネットワーク防御であり、SIEM ソリューションは脅威ハンティングチームのためにセキュリティ情報を集約する |

## 関連用語

SEM、SIM、SIEM という略語は互換的に使われることもあるが、一般には主な重点が異なる製品を指す。

| 用語 | 主な重点 |
| --- | --- |
| ログ管理 | ログメッセージと監査証跡の単純な収集と保存 |
| セキュリティ情報管理（SIM） | ログデータの長期保存、分析、レポート作成 |
| セキュリティイベントマネージャー（SEM） | リアルタイム監視、イベントの相関分析、通知、コンソール表示 |
| SIEM | SIM と SEM を組み合わせ、ネットワーク機器やアプリケーションからのセキュリティアラートのリアルタイム分析を提供する |

実際には多くの製品がこれらの機能を混在させており、多くのベンダーが独自の用語を打ち出している。ログ管理だけではネットワークセキュリティについてリアルタイムの洞察は得られず、SEM 単体では詳細な脅威分析に必要な完全なデータは得られない。両者を組み合わせることで、SIEM はより多くの情報を監視できるようになる。

## 機能と構成要素

| 機能 | 説明 |
| --- | --- |
| データ集約 | 重要なイベントを見逃さないよう、ネットワーク、セキュリティ機器、サーバー、データベース、アプリケーションから監視データを統合する |
| 相関分析 | 共通の属性を持つイベントを結びつけ、意味のあるまとまりにする。通常は SIEM の SEM 部分の機能である |
| アラート | 相関付けられたイベントの自動分析 |
| ダッシュボード | イベントデータをグラフに変換し、パターンやそこから外れた活動を見つけやすくする |
| コンプライアンス | コンプライアンスデータの収集を自動化し、既存のセキュリティ・ガバナンス・監査プロセス向けのレポートを作成する |
| 保持 | 経時的な相関分析とコンプライアンスのための履歴データの長期保存。侵害は発生した時点で発見される可能性が低いため、フォレンジック調査において極めて重要である |
| フォレンジック分析 | 特定の条件によって、ノードや期間をまたいでログを検索する |

アーキテクチャはベンダーによって異なるが、必須の構成要素は次のとおりである。ホストから選択した監査ログを転送するデータコレクター、解析・相関分析・データ正規化を行う取り込み・インデックス作成ポイント、そして分析が行われる場であり、可視化、クエリ、レポート、アラートを担う検索ノードである。

## ユースケースとルール

コンピュータセキュリティ研究者の Chris Kubecka は、ハッキングカンファレンス 28C3（Chaos Communication Congress）で SIEM のユースケースを一通り紹介した。その中には次のようなものが含まれる。SIEM による可視性と[[DefinedTerm/anomaly-detection|異常検知]]を用いて、アンチウイルスの検出率が低いゼロデイやポリモーフィック型コードの検知に役立てること。ログを送信できるあらゆるデバイスからのログを自動的に解析・正規化・分類すること。セキュリティイベントやログの欠落を可視化してパターンの発見に役立てること。設定ミスやセキュリティ上の問題を示している可能性のあるプロトコルの異常を特定すること。秘匿された悪意ある通信や暗号化されたチャネルを検知すること。そしてサイバー戦を検知し、攻撃者と被害者の両方を突き止めることである。

SIEM には、単純なものから複雑なものまで、数百から数千の相関ルールが存在しうる。ルールが発動すると、システムは攻撃を緩和するための措置をとることができる。通常はユーザーに通知し、場合によってはシステムを制限または停止する。挙げられているルールの種類には、ブルートフォース検知（たとえば 1 分間に 60 回パスワードが入力される）、不可能な移動（ログインの時刻と場所から、実際にはありえない移動が示唆されるもの。VPN サービスによって位置が隠される場合を考慮する必要があるルールである）、過剰なファイルコピー（攻撃者を示している可能性もあるが、従業員がファイルを売却している、あるいは単に自宅に持ち帰っている可能性もある）、ネットワークの異常検知、DDoS 攻撃、ファイル整合性の変更監視がある。アラートルールは通常、ユーザー認証、検知された攻撃、検知された感染に基づいて構築される。たとえば、単一のホストから 1 分間に 3 回以上ログインに失敗した場合に、ブルートフォース攻撃、パスワード推測、あるいは設定ミスのあるアプリケーションの早期警告としてアラートを出すもので、イベントは Active Directory、syslog、RADIUS などのソースから取得される。あるいは、検知されたマルウェアをホストが 1 時間以内に駆除できなかった場合にアラートを出すものもある。
