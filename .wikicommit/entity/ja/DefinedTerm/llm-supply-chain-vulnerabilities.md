LLM のサプライチェーンの脆弱性とは、大規模言語モデル（LLM）を基盤とするアプリケーションのサプライチェーンにおける弱点であり、訓練データ、モデル、デプロイ基盤の完全性に影響して、偏った出力、セキュリティ侵害、システム障害をもたらしうるものである。[[DefinedTermSet/owasp-top-10-for-llm-applications|OWASP Top 10 for LLM Applications]] の2025年版の項目 LLM03:2025「Supply Chain」を構成する。この項目によれば、従来のソフトウェアの脆弱性はコードの欠陥や依存関係といった問題が中心であるのに対し、機械学習ではリスクがサードパーティの事前訓練済みモデルやデータにも及び、それらは改ざんやポイズニング攻撃によって操作されうる。サプライチェーン攻撃一般については[[DefinedTerm/supply-chain-attack|サプライチェーン攻撃]]を参照。

## LLM のサプライチェーンが攻撃にさらされる理由

OWASP の項目は、LLM の作成は専門的な作業であり、サードパーティのモデルに依存することが多いと説明している。オープンアクセスの LLM の台頭や、LoRA（Low-Rank Adaptation）や PEFT（Parameter-Efficient Fine-Tuning）といった新しいファインチューニング手法の登場は、特に Hugging Face のようなプラットフォームにおいて、新たなサプライチェーンのリスクをもたらしている。また、デバイス上の LLM は攻撃対象領域をさらに広げる。同じリスクの一部は LLM04「Data and Model Poisoning」でも扱われており、サプライチェーンの項目はそのサプライチェーンの側面に焦点を当てている。

## よくあるリスク

| リスク | 内容 |
| --- | --- |
| 従来型のサードパーティパッケージの脆弱性 | 攻撃者が LLM アプリケーションを侵害するために悪用する、古くなった、あるいは非推奨のコンポーネント。OWASP の「A06:2021 – Vulnerable and Outdated Components」と同様だが、そのコンポーネントがモデルの開発やファインチューニングの際に使われる場合にはリスクが高まる |
| ライセンスのリスク | AI 開発にはさまざまな法的要件をもつ多様なソフトウェアやデータセットのライセンスが関わり、データセットのライセンスは利用、配布、商業化を制限することがある |
| 古くなった、あるいは非推奨のモデル | もはや保守されていないモデルはセキュリティ上の問題につながる |
| 脆弱な事前訓練済みモデル | モデルはバイナリのブラックボックスであり、静的な検査ではほとんど保証が得られない。モデルリポジトリの安全性評価で見落とされた、隠れたバイアス、バックドア、その他の悪意ある機能を含んでいることがあり、それらは汚染されたデータセットや、ROME（ロボトミー化とも呼ばれる）などの手法による直接的なモデルの改ざんによって作られる |
| 弱いモデルの来歴 | 公開されたモデルには強い来歴の保証がない。モデルカードや文書はモデルの出所を保証せず、攻撃者はモデルリポジトリ上の供給者のアカウントを侵害したり、類似のアカウントを作成したりして、ソーシャルエンジニアリングと組み合わせることができる |
| 脆弱な LoRA アダプタ | 悪意ある LoRA アダプタは、協調的なモデルマージ環境においても、デプロイ済みのモデルにアダプタをダウンロードして適用する vLLM や OpenLLM などの推論プラットフォームを通じても、事前訓練済みのベースモデルの完全性とセキュリティを損なう |
| 協調開発の悪用 | 共有のモデルマージサービスや、形式変換などのモデル処理サービスが悪用され、共有モデルに脆弱性が持ち込まれうる。モデルマージは Hugging Face で非常に人気があり、レビューの回避に使われうる |
| デバイス上のサプライチェーン | 侵害された製造プロセスや、デバイスの OS やファームウェアの脆弱性がモデルを侵害しうる。また攻撃者は、アプリケーションをリバースエンジニアリングし、改ざんしたモデルとともに再パッケージ化できる |
| 不明確な利用規約とプライバシーポリシー | モデル運営者の不明確な利用規約やデータプライバシーポリシーは、アプリケーションの機密データが訓練に使われ、後に露出することにつながりうる。また、供給者による著作物の使用に起因するリスクをもたらすこともある |

## 予防と緩和

この項目は10の対策を推奨している。

1. 利用規約やプライバシーポリシーを含め、データソースと供給者を慎重に審査し、信頼できる供給者のみを使い、そのセキュリティとアクセスを定期的に見直し、監査する。
2. OWASP の「A06:2021 – Vulnerable and Outdated Components」の緩和策（脆弱性のスキャン、管理、パッチ適用）を、機密データにアクセスできる開発環境も含めて適用する。
3. モデルは Decoding Trust のような公開ベンチマークを回避するようファインチューニングされうるため、サードパーティのモデルを選定する際には包括的な AI の[[DefinedTerm/red-team|レッドチーミング]]と評価を行う。
4. ソフトウェア部品表（SBOM）によって、最新かつ正確で署名されたコンポーネントの一覧を維持する。これは新たな脆弱性の迅速な検出にも役立ちうる。AI BOM や ML SBOM は新興の分野であり、項目は OWASP CycloneDX から始めることを提案している。
5. BOM に保持するライセンスの一覧、ソフトウェア・ツール・データセットの定期的な監査、自動化されたライセンス管理ツール、チームの訓練によって、AI のライセンスのリスクを管理する。
6. 検証可能な情報源からのモデルのみを使い、弱いモデルの来歴を補うために署名とファイルハッシュを用いたサードパーティによる完全性チェックを行い、外部から供給されるコードにはコード署名を用いる。
7. 「HuggingFace SF_Convertbot Scanner」のような自動化されたスクリプトを用いて、協調的なモデル開発環境を厳格に監視・監査する。
8. 供給されたモデルとデータに対して[[DefinedTerm/anomaly-detection|異常検知]]と敵対的頑健性のテストを行い、改ざんや[[DefinedTerm/data-poisoning|ポイズニング]]を検出する。理想的には MLOps や LLM のパイプラインの中で行うが、新興の手法であるため、レッドチーミング演習の中で適用するほうが容易な場合がある。
9. 脆弱な、あるいは古くなったコンポーネントのためのパッチ適用ポリシーを維持し、保守されているバージョンの API と基盤モデルに依拠する。
10. AI エッジにデプロイされたモデルを完全性チェック付きで暗号化し、ベンダーの構成証明（attestation）API を用いて、改ざんされたアプリやモデルを防ぎ、認識されないファームウェア上のアプリケーションを終了させる。

## 攻撃シナリオの例

この項目は13のシナリオ例を挙げており、そのいくつかは実際の攻撃として示されている。

| シナリオ | 項目が説明する内容 |
| --- | --- |
| 脆弱な Python ライブラリ | 攻撃者が脆弱な Python ライブラリを通じて LLM アプリを侵害する。項目によれば、これは OpenAI の最初のデータ侵害で起きたことである。PyPI レジストリへの攻撃では、モデル開発者を騙してマルウェアを含む侵害された PyTorch の依存関係をダウンロードさせた。Ray AI フレームワークに対するより高度な Shadow Ray 攻撃では、5つの脆弱性が実際に悪用されたと考えられており、多くのサーバーに影響した |
| 直接的な改ざん | モデルが直接改ざんされ、誤情報を広めるために公開される。実際の攻撃である PoisonGPT は、モデルのパラメータを変更することで Hugging Face の安全機能を回避した |
| 人気モデルのファインチューニング | 攻撃者が人気のオープンアクセスモデルをファインチューニングし、安全性ベンチマークでは高いスコアを得つつ、標的型のトリガーによって主要な安全機能を取り除き、ベンチマークに対するユーザーの信頼を悪用するために Hugging Face にデプロイする |
| 事前訓練済みモデル | あるシステムが、広く使われているリポジトリの事前訓練済みモデルを十分な検証なしにデプロイし、侵害されたモデルが悪意あるコードを持ち込んで、特定の文脈で偏った、操作された出力を引き起こす |
| 侵害されたサードパーティの供給者 | 侵害された供給者が脆弱な LoRA アダプタを提供し、それが Hugging Face 上のモデルマージによって LLM にマージされる |
| 供給者への潜入 | 攻撃者が供給者に潜入し、vLLM や OpenLLM などのフレームワークでデプロイされたデバイス上の LLM 向けの LoRA アダプタを改変する。これにより攻撃者は秘密の侵入口と、モデルの出力を操作する能力を得る |
| CloudBorne と CloudJacking | クラウド基盤に対する攻撃。CloudBorne は共有クラウド環境のファームウェアの脆弱性を悪用して仮想インスタンスをホストする物理サーバーを侵害し、CloudJacking はクラウドインスタンスの悪意ある制御や悪用であり、LLM のデプロイ基盤へのアクセスを与えうる |
| LeftOvers（CVE-2023-4969） | 漏洩した GPU のローカルメモリを悪用して、本番サーバー、開発用ワークステーション、ノートパソコンから機密データを復元し、持ち出す |
| WizardLM | WizardLM が削除された後、攻撃者がマルウェアとバックドアを含む同名の偽モデルを公開する |
| モデルマージや形式変換のサービス | 攻撃者がモデルマージや形式変換のサービスを使って、公開されているモデルにマルウェアを注入する。ベンダー HiddenLayer が公表した実際の攻撃である |
| リバースエンジニアリングされたモバイルアプリ | 攻撃者がモバイルアプリ内のモデルを、ユーザーを詐欺サイトに誘導する改ざんされたモデルに置き換える。項目はこれを、セキュリティや安全性が重要なものを含む116の Google Play アプリに影響した、予測型 AI に対する実際の攻撃として説明している |
| データセットのポイズニング | 汚染された公開データセットが、ファインチューニング中に特定の企業をひそかに優遇するバックドアを作り出す |
| 利用規約とプライバシーポリシー | LLM の運営者が利用規約を変更し、アプリケーションのデータを訓練に使わないためには明示的なオプトアウトが必要になった結果、機密データが記憶されてしまう |

この項目は、これらのリスクを MITRE ATLAS の技術 AML.T0010「ML Supply Chain Compromise」と関連づけている。
