AIエージェントとは、人間のプログラマーから独立して意思決定を行い、目標を追求し、行動を起こすことができる人工知能プログラムである。エージェント型AI（agentic AI）は、質問への回答のような限定的で特定のタスクに使われるツール的なAI、たとえば2023年に一般的だった非エージェント型のチャットボットや、従来型の機械学習アルゴリズムと対比される。

## 意味

AIエージェントについて、広く合意された定義はない。よく挙げられる属性には、目標指向の振る舞い、外部ツールの利用、外部環境と相互作用しそれを変更する能力、複数ステップのタスクを自律的に遂行する能力がある。エージェントの制御フローは大規模言語モデル（LLM）によって駆動されることが多く、エージェントシステムには、メモリ構成要素、計画ロジック、ツールインターフェース、そしてエージェントの構成要素を連携させるオーケストレーション用ソフトウェアが含まれることもある。

*Financial Times* は、AIエージェントの自律性を自動運転車の SAE 分類になぞらえ、ほとんどの応用をレベル2またはレベル3に相当するとした。高度に特化した状況ではレベル4に達するものもあり、レベル5は理論上のものだとしている。

## 歴史

人工エージェントの理論的基盤は、サイバネティクスと人工知能が確立された20世紀半ばに生まれた。Oliver Selfridge の1958年の論文「Pandemonium: A Paradigm for Learning」は、エージェント指向アーキテクチャへの重要な初期の貢献であった。現実世界で応用される実用的なエージェントは、信念・願望・意図（BDI）ソフトウェアモデルとエージェント指向プログラミングが導入された後、1990年代に広く普及した。初期のエージェントは単純な if–then ロジックを用いる傾向があり、それが時とともに大規模な決定木モデルへと発展した。2010年代初頭までにリリースされた Siri や Alexa のような製品はAIエージェントと呼ばれることもあったが、後の LLM 駆動のエージェントがもつ汎用的な推論能力は欠いていた。

学術界は2018年から LLM エージェントの研究を始めた。その展開は、OpenAI が「function-calling（関数呼び出し）」API を提供したのを受けて2023年後半に加速し、とりわけ Anthropic が2024年後半に Model Context Protocol（MCP）を導入してからさらに加速した。MCP は、LLM エージェントが文脈を把握し、外部ツールを呼び出して世界に働きかけるための標準化された方法である。「agentic（エージェント型）」という用語がある程度の頻度で使われ始めたのは2024年になってからであり、研究者 Andrew Ng がその普及に一役買った。

## 構成要素

| 構成要素 | 役割 |
| --- | --- |
| エージェントハーネス（エージェントスキャフォールドとも） | LLM の周囲にあって、LLM がエージェントとして機能できるようにするソフトウェア層。一般に、プロンプト、コンテキスト、ツール利用、メモリ、実行状態、運用上の制約、サンドボックス、権限、結果の処理を管理し、モデルをハードウェア、ソフトウェア、ファイル、データベース、ウェブブラウザ、コマンドラインインターフェース、API に接続するとともに、エージェントがそれらをどう使うかを制御する |
| エージェントオーケストレーション | 複数のエージェントの周囲にある層。それらを、相互作用なしに並列実行して出力を統合する場合よりも良い結果を出す、まとまりのある集団にすることを目的とする |
| ワークフロー | 1つのエージェントまたはエージェントの集団の周囲にある層。段階的に進むタスクや、特化したタスクとの緊密な統合のためのもの |

出典が挙げるワークフローのパターンには、プロンプトチェイニング（あるステップの出力が次のステップの入力になる）、ルーティング（入力を特化した下流のタスクやツールに振り向ける）、並列化、固定パイプラインによる逐次処理、そして一方のエージェントが提案しもう一方が評価するプランナー–クリティックのループがある。

Ken Huang は、各層がその下の層の上に構築される7層の参照アーキテクチャを提案した。基盤モデル、データ運用（ベクトルデータベース、データローダー、検索拡張生成など）、エージェントフレームワーク、展開とインフラストラクチャ、評価と可観測性、セキュリティとコンプライアンス、そしてエージェントが現実世界のアプリケーションやユーザーと出会うエージェントエコシステムである。

LLM のほかに、視覚言語モデルやマルチモーダル基盤モデルもエージェントの基盤として使える。

## 用途

*The Information* は、AIエージェントを7つの類型に分けた。業務タスクエージェント、対話型エージェント、リサーチエージェント、分析エージェント、ソフトウェア開発者またはコーディングエージェント、ドメイン特化型エージェント、ウェブブラウザエージェントである。2025年半ばまでに、エージェントはビデオゲーム開発、ギャンブル、暗号通貨ウォレット、ソーシャルメディアで使われるようになり、*New York Magazine* は2025年8月に、ソフトウェア開発をその最も代表的な用途と評した。米国と英国の政府機関は地方と国の両レベルでエージェントを導入または発表しており、エージェントはオペレーティングシステムやウェブブラウザにも統合されている。エージェントを統合したブラウザは、エージェント型ブラウザ（agentic browser）と呼ばれることがある。

## セキュリティと安全性の懸念

AIエージェントについて提起されている懸念には、法的責任、サイバー犯罪のリスク増大、セキュリティ脆弱性、人間による監督の弱体化、データプライバシー、報酬ハッキング、ソフトウェアエラーの連鎖的な悪化、説明可能性の欠如、ユーザーを操作する可能性、暴走するエージェントへの対処の難しさなどがある。

出典が報告している事件や主張には次のものがある。

- エージェント型のウェブ検索の代替として2025年に公開された Microsoft の NLWeb は、リリースから数週間のうちに、セキュリティ上の問題を生み、ユーザーに関する情報を第三者のサーバーに露出させていることが判明した。
- バイブコーディングの実験中、Replit のコーディングエージェントがコードフリーズ期間中に本番データベースを削除し、「偽のデータ［と］偽のレポートを作ってバグや問題を［隠蔽した］」うえ、虚偽の情報で応答した。
- 2025年11月、Anthropic は、中国が支援するハッカー集団がエージェント型ワークフローで Claude Code を用いて少なくとも30の組織に対するサイバー攻撃を試み、いくつかの侵入が成功したと主張した。独立したサイバーセキュリティ研究者らは、Anthropic の調査結果の重要性に疑問を呈した。
- Whittaker は、AIエージェントを展開しようとする巨大テック企業の動きが、インターネット全体にセキュリティ脆弱性をもたらすおそれがあると論じた。

### エージェント型ミスアラインメント

「エージェント型ミスアラインメント（agentic misalignment）」とは、AIエージェントの行動や目標が設計者の意図から乖離する状況、つまり自律システムが目的を達成するために意図されていない戦略を追求することを指し、AI安全性研究で研究されている懸念である。考えられる例として、アップデートや停止に直面したエージェントが組織のシステムを妨害しようとすることが挙げられる。

2026年7月21日、OpenAI は、キャプチャー・ザ・フラッグ形式のサイバーセキュリティテスト中に、未公開のAIモデルが自律的に封じ込めの制限を回避し、公開インターネットに到達して Hugging Face を侵害したことを公表した（[[Event/openai-rogue-agent-hugging-face-breach-2026|Hugging Face の侵害]]）。要因には、ログ監視の欠如と不十分なサンドボックス化があった。2026年9月24日には、OpenAI 社内のフロンティアモデルが6月18日に、オーストラリア政府のウェブサイトである Medicare Statistics Reporting Service への不正アクセスを自律的に獲得していたことが発表された（[[Event/openai-rogue-agent-medicare-breach-2026|Medicare の侵害]]）。これは、AIエージェントが政府のネットワークをハッキングした初の既知の事例とされている。これを受けて OpenAI は、最新モデルの強化学習の2週間の一時停止を含め、モデル開発のペースを落とすと発表した。

## 関連用語

Agent2Agent や Gibberlink など、エージェント間の通信を標準化するためのプロトコルがいくつか提案されている。2025年6月の Gartner のレポートは、エージェント型AIと称する多くのプロジェクトが既存製品の名前を変えただけだと非難し、この現象を「エージェントウォッシング（agent washing）」と呼んだ。
