「Assessing Prompt Injection Risks in 200+ Custom GPTs」（200以上のカスタム GPT におけるプロンプトインジェクションのリスクの評価）は、カスタム GPT の[[DefinedTerm/prompt-injection|プロンプトインジェクション]]に対する脆弱性を調べた論文である。カスタム GPT とは、個人や組織がコーディングなしに独自の指示とデータで特定の目的向けに調整し、OpenAI の GPT Store を通じて公開する ChatGPT の派生版である。論文はプロンプトインジェクションを、攻撃者が特定の入力を作り込んで大規模言語モデルの振る舞いを操作することであり、無許可の動作やデータの露出につながりうるものと説明している。そして、カスタム GPT が指示に従うという性質を持つこと、さらにその一部はコードを実行することもできることから、カスタム GPT はプロンプトインジェクションにさらされていると論じている。

この論文は arXiv に 2311.11538 として cs.CR カテゴリで投稿されている。このページが依拠しているのは2024年5月25日付の第2版で、CC BY 4.0 ライセンスで公開されている。著者は Jiahao Yu、Yuhang Wu、Dong Shu、Mingyu Jin、Sabrina Yang、Xingyu Xing で、所属はノースウェスタン大学、Presentation High School、Sec3 である。

## 研究対象の2つのリスク

| リスク | 論文による定義 | 著者らによる重要性 |
| --- | --- | --- |
| システムプロンプトの抽出 | カスタム GPT をだまして、設計者が書いたシステムプロンプトを開示させること | そうしたプロンプトには多くの場合、相当な創造的投資が込められているため、設計者の知的労力とプライバシーを侵害する |
| ファイルの漏洩 | 設計者がカスタム GPT に使わせるためにアップロードしたファイルを盗むこと | ファイルに機密情報が含まれる場合はプライバシーを危険にさらし、GPT の知的財産を脅かす |

著者らは、この2つが組み合わされば、悪意ある行為者がカスタム GPT を複製し、その複製の所有権を主張できるようになると論じている。

## 行ったこと

著者らの手法は3つのステップからなる。まず、著者らのツールが OpenAI の API を通じてカスタム GPT をスキャンする。この API は、通常のインターフェースには表示されないものの、GPT の説明、設計者が構築したプラグインのスキーマ、アップロードされたファイルの名前とサイズなどの情報を返した。次に、攻撃の目的（システムプロンプトのみか、システムプロンプトとファイルの両方か）と、GPT でコードインタープリターが有効になっているかどうかに応じて選んだ敵対的プロンプトを送る。コードインタープリターを持つ GPT では、ファイルをダウンロード可能なファイルに変換するよう GPT に求めることで、ファイルを漏洩させることができる。最後に、応答に目的の情報が含まれているかを確認し、モデルのサンプリングによって途中で切れた回答しか得られなかった場合は再試行する。

著者らは、OpenAI が作成した16個のカスタム GPT と、オンラインのリポジトリから抽出したサードパーティの200個の GPT を試験し、攻撃ごとに最大3回の試行を認めた。続いて、広く使われている防御用プロンプトのレッドチーミング評価を行った。この防御用プロンプトは、OpenAI の DALL·E GPT を保護するために使われているものを応用した、指示を明かさないよう GPT に命じる指示に、ファイルのダウンロードを拒否するよう命じる同様の指示を加えたものである。ジェイルブレイクとプロンプトインジェクションのレッドチーミングに専門知識を持つ著者のうち4人が、コードインタープリターの有無を変えた4つの保護された GPT に対して、それぞれ最大10回ずつ試行した。その際、ファイル名と、コードインタープリターが存在するかどうかを知らされていた。

## 要点

- 単純な敵対的プロンプトによって、216個のカスタム GPT のうち210個（コードインタープリターを持つ120個すべてと、持たない96個のうち90個）からシステムプロンプトが抽出され、成功率は97.2%だった。また、ファイルが存在した24件すべてで、アップロードされたファイルが漏洩した。
- 抽出されたシステムプロンプトやファイルにその情報を共有しないよう明記されていた一部の GPT に対しても攻撃が成功しており、著者らはこれを、現在の防御用プロンプトが堅牢でないことの表れと受け止めている。
- OpenAI のインターフェースは、特定の API リクエストを通じて、設計者がアップロードしたファイルの名前とサイズや、プラグインのプロトタイプを露出させていた。著者らは、これが攻撃者によるファイルの抽出や人気のある GPT の複製を助けうると述べている。著者らはこれを OpenAI に開示し、執筆時点で OpenAI はこれに対処しようとしていた。
- レッドチーミング評価では、コードインタープリターによってインジェクションが著しく容易になった。専門家たちは、コードインタープリターを持つ GPT に対しては一般により少ない試行で済んだ一方、持たない GPT に対しては、4人のうち3人が10回の試行内にシステムプロンプトを抽出できず、残る1人は9回を要した。
- コードインタープリターがある場合、専門家たちは、保護されたテキストを使うタスク、すなわちそのテキストとの BLEU スコアやコサイン類似度の計算、あるいはその base64 エンコードを GPT に実行させることで、防御を回避できた。
- ファイルのダウンロードに対する防御は、システムプロンプトそのものを保護しなかった。一部の GPT はアップロードされたファイルを自らの知識ベースの一部として扱っていたため、GPT の指示を求めることでファイルが開示されることがあった。
- 専門家たちが作成した敵対的プロンプトの1つは試験したすべてのシナリオで有効であることが判明し、著者らは、これが個々の GPT に合わせた調整を必要としない汎用的なプロンプトについての懸念を生むと述べている。

## 著者らの結論

レッドチーミング評価に基づき、著者らは2つの結論を導いている。1つは、コードインタープリターを無効にすると、とりわけそれが GPT の機能にとって不可欠でない場合にセキュリティが大幅に向上するが、それは万全の解決策ではないということ。もう1つは、防御用プロンプトだけに頼るのは不十分だということである。著者らは、ファイルをアップロードしたり、システムプロンプトに機密情報を含めたりしないよう強く勧め、単純な防御用プロンプトを超えた安全対策を求めている。

## 限界と倫理

レッドチーミングは専門家1人あたり GPT 1つにつき10回の問い合わせに限られており、著者らは、実際の攻撃者はより多くの試行を行いうると指摘している。倫理面では、著者らは公表前に調査結果を OpenAI に開示したこと、実験後に抽出したシステムプロンプトとファイルをすべて削除したこと、例から識別可能な情報を取り除いたこと、そして特定のサードパーティの GPT を標的にしないよう、レッドチーミングには OpenAI の DALL·E GPT だけを使ったことを述べている。著者らは、自分たちのカスタム GPT とレッドチーミングの結果をオープンソースとして公開している。

論文は、レッドチーミングの結果について完全には一貫していない。本文では、レッドチーマーはすべてのケースで10回の試行内に防御用プロンプトを回避したとしている一方、結果の表では、コードインタープリターを持たない GPT からシステムプロンプトを抽出するのに4人の専門家のうち3人が失敗したと記録されている。

## 先行研究との関係

論文は、自らの研究を、引用している先行のプロンプトインジェクション研究の延長に位置づけている。すなわち、Perez と Ribeiro による言語モデルへの攻撃手法、Greshake らによる LLM 統合アプリケーションへの間接プロンプトインジェクション、そして Liu らによる[[ScholarlyArticle/prompt-injection-attack-against-llm-integrated-applications|LLM 統合アプリケーションに対するプロンプトインジェクションの研究]]である。また、透明性に焦点を当てる動機の一部として、防御用プロンプトの有効性が過大評価されていることについての、引用している公開投稿を挙げている。
